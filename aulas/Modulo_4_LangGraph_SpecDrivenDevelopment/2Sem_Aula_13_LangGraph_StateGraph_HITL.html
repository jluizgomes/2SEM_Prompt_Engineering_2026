Glossário

StateGraph
Classe do LangGraph que representa o grafo como objeto: recebe um schema de estado (TypedDict), agrega nodes com add_node() e edges com add_edge()/add_conditional_edges(), e compila em um grafo executável.
TypedDict (estado do grafo)
Estrutura tipada que define os campos do estado compartilhado entre nodes — cada node lê parte dela e retorna um dicionário parcial de atualização.
add_conditional_edges()
Método que registra uma aresta cujo próximo node é escolhido em tempo de execução por uma função de roteamento, permitindo loops e desvios condicionais no grafo.
draw_mermaid()
Método que gera automaticamente o diagrama Mermaid do grafo compilado — código e documentação visual nunca dessincronizam, pois vêm da mesma fonte.
MemorySaver
Checkpointer do LangGraph que persiste o estado do grafo por thread_id, permitindo retomar uma execução exatamente de onde parou.
thread_id
Identificador usado pelo MemorySaver para isolar o histórico de estado de execuções distintas do mesmo grafo — equivalente ao session_id de uma conversa.
interrupt_before
Parâmetro de compilação que pausa a execução do grafo antes de um node específico, esperando aprovação humana antes de prosseguir — mecanismo central do HITL.
HITL (Human-in-the-loop)
Padrão onde a execução automática é interrompida em pontos críticos para que uma pessoa revise ou aprove antes de uma ação irreversível continuar.

from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from typing import TypedDict, Annotated
from langchain_ollama import ChatOllama
from langchain_core.messages import HumanMessage
import os
from google.colab import userdata

os.environ["OLLAMA_HOST"]    = "https://ollama.com"
os.environ["OLLAMA_API_KEY"] = userdata.get("OLLAMA_API_KEY")
llm = ChatOllama(model="gpt-oss:120b", temperature=0)

# 1. Definir o Estado com TypedDict
class Estado(TypedDict):
    # Annotated[list, add_messages] usa reducer que ACUMULA (nao substitui)
    mensagens: Annotated[list, add_messages]
    iteracoes: int   # campo simples — substituido a cada update
    rota: str         # campo simples — a decisao do classificador

# 2. Definir Nodes — funcoes que recebem state e retornam dict
def node_responder(state: Estado) -> dict:
    resposta = llm.invoke(state["mensagens"])
    return {
        "mensagens": [resposta],  # add_messages ACUMULA — nao substitui
        "iteracoes": state["iteracoes"] + 1,
    }

# 3. Construir o Grafo
builder = StateGraph(Estado)
builder.add_node("responder", node_responder)
builder.add_edge(START, "responder")
builder.add_edge("responder", END)

# 4. Compilar — valida e retorna Runnable
app = builder.compile()

# 5. Invocar como qualquer chain LCEL
resultado = app.invoke({"mensagens": [HumanMessage("Oi!")], "iteracoes": 0, "rota": ""})
print(resultado["mensagens"][-1].content)

add_conditional_edges() — o superpoder do LangGraph

O Router da Aula 12 em codigo Python. Com LangGraph, a condicao fica explicita no grafo — visivel, testavel e visualizavel com draw_mermaid():

conditional_edges.py
from langgraph.graph import StateGraph, START, END
from pydantic import BaseModel
from typing import TypedDict, Annotated, Literal
from langgraph.graph.message import add_messages

class Estado(TypedDict):
    mensagens: Annotated[list, add_messages]
    rota: str
    iteracoes: int

class Rota(BaseModel):
    destino: Literal["rag", "calculadora", "conversa"]

# Node: classifica a intencao e escreve "rota" no estado
def node_classificar(state: Estado) -> dict:
    ultima_msg = state["mensagens"][-1].content
    rota_obj   = chain_clf.invoke({"input": ultima_msg})
    return {"rota": rota_obj.destino}

# Funcao de roteamento — le o estado e retorna string
def decidir_rota(state: Estado) -> str:
    return state["rota"]  # deve retornar uma das chaves do mapa abaixo

builder = StateGraph(Estado)
builder.add_node("classificar", node_classificar)
builder.add_node("rag",         node_rag)
builder.add_node("calculadora", node_calc)
builder.add_node("conversa",    node_chat)
builder.add_edge(START, "classificar")

# add_conditional_edges(no_origem, fn_rota, {retorno_fn: nome_no_destino})
builder.add_conditional_edges(
    "classificar",
    decidir_rota,
    {"rag":"rag", "calculadora":"calculadora", "conversa":"conversa"},
)
for no in ["rag", "calculadora", "conversa"]:
    builder.add_edge(no, END)
app = builder.compile()

MemorySaver — estado persistente por thread_id

Sem MemorySaver, cada app.invoke() comeca do zero. Com MemorySaver, o estado e salvo por thread_id e recuperado na proxima chamada:

memorysaver.py
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()

# Compilar COM checkpointer — habilita persistencia e HITL
app = builder.compile(checkpointer=checkpointer)

# thread_id identifica a "sessao" — cada usuario tem seu proprio thread
config_u1 = {"configurable": {"thread_id": "usuario_01"}}
config_u2 = {"configurable": {"thread_id": "usuario_02"}}

# Chamada 1 — usuario 01
app.invoke(
    {"mensagens": [HumanMessage("Qual o prazo de garantia?")],
     "rota":"", "iteracoes":0},
    config=config_u1,
)

# Chamada 2 — mesmo usuario 01 — historico preservado
r = app.invoke(
    {"mensagens": [HumanMessage("E a multa por rescisao?")]},
    config=config_u1,
)
print(len(r["mensagens"]))  # → 4 (2 Human + 2 AI acumulados)

# Inspecionar o estado salvo
snapshot = app.get_state(config_u1)
print(f"Iteracoes: {snapshot.values['iteracoes']}")
print(f"Proximo no: {snapshot.next}")  # [] se terminou, ['nome'] se pausado
MemorySaver vs ConversationBufferMemory (Aula 02)
ConversationBufferMemory guarda apenas mensagens para 1 conversa por vez. MemorySaver guarda todo o estado do grafo (incluindo campos customizados) e suporta multiplas sessoes paralelas por thread_id. Para producao real, usar SqliteSaver ou PostgresSaver (a API e identica, so troca o checkpointer).

HITL com interrupt_before — aprovacao antes de acao irreversivel

hitl.py
from langgraph.checkpoint.memory import MemorySaver

# Compilar COM interrupt_before — pausa ANTES do no especificado
app_hitl = builder.compile(
    checkpointer=MemorySaver(),
    interrupt_before=["enviar_email"],  # pausa ANTES deste no
)

config = {"configurable": {"thread_id": "tarefa_01"}}

# FASE 1 — rodar ate a pausa
app_hitl.invoke(
    {"mensagens": [HumanMessage("Gere um rascunho de email")]},
    config=config,
)
# → nos anteriores executaram, PAUSOU antes de "enviar_email"
# → estado salvo no MemorySaver — thread "suspensa"

# FASE 2 — humano le o rascunho
snapshot = app_hitl.get_state(config)
print(f"Rascunho: {snapshot.values['mensagens'][-1].content}")
print(f"No suspenso: {snapshot.next}")  # → ('enviar_email',)

# FASE 3a — humano aprova → continuar (input=None)
aprovado = input("Aprovar envio? (s/n): ")
if aprovado.lower() == "s":
    app_hitl.invoke(None, config=config)  # None = retomar sem novo input
    print("Email enviado!")
# FASE 3b — humano edita → update_state() antes de retomar
else:
    nova_msg = HumanMessage(input("Editar rascunho: "))
    app_hitl.update_state(config, {"mensagens": [nova_msg]})
    app_hitl.invoke(None, config=config)
Por que HITL e essencial em producao
Acoes irreversiveis (enviar email, debitar conta, publicar post, deletar registro) nunca devem ser executadas autonomamente sem revisao humana. interrupt_before garante que o humano sempre aprova antes de agir — independentemente do que o LLM decidiu. Essa e a diferenca entre um sistema confiavel e um risco operacional.
📖 Fundamentação — HITL como fase de confiança, não trava permanente
Bornet e Wirtz (Agentic Artificial Intelligence, World Scientific, 2025) descrevem human-in-the-loop com uma analogia direta: trate o agente como um funcionário recém-contratado — ninguém deixa uma contratação recente operar sem supervisão, e o mesmo vale para um agente de IA. Os autores enquadram HITL como algo especialmente importante nas fases iniciais de adoção, não como trava permanente: a colaboração funciona quando o humano mantém controle sobre metas e revisa decisões críticas, sobretudo em áreas de risco alto como financeiro ou saúde. Essa é uma camada que complementa o critério desta aula: além de "essa ação pode ser desfeita?", vale perguntar "quanto esse agente já provou ser confiável nessa tarefa?" — o mesmo nó pode justificar interrupt_before hoje e dispensá-lo depois de meses de execução sem erro.

O grafo pesquisador — loop visivel no draw_mermaid()

A aresta de volta avaliar → buscar cria um ciclo — impossivel em chains LCEL, explicito em LangGraph e visivel no diagrama Mermaid:

__start__
↓
buscar
DuckDuckGo · incrementa iteracoes
↓
avaliar
LLM-as-judge · grava qualidade
qualidade≥0.7 ou iter≥3
↓
responder
↓
__end__
qualidade<0.7 e iter<3
↺
volta para
buscar
O ciclo e o diferencial — e o risco
A aresta avaliar → buscar cria um ciclo. Sem o limite MAX_ITER, o grafo poderia executar infinitamente. Sempre incluir uma condicao de saida baseada em contagem de iteracoes — nunca confiar so na qualidade para parar o loop.
📖 Fundamentação — Producer-Critic, não autoavaliação
Gullí (Agentic Design Patterns, O'Reilly, 2025, cap. 4 — Reflection) nomeia o padrão deste grafo: um agente que avalia a própria saída e usa essa avaliação para refinar o resultado, em vez de aceitar a primeira tentativa. O autor recomenda especificamente separar quem gera de quem avalia — o modelo "Producer-Critic" — porque pedir que o mesmo agente critique seu próprio trabalho carrega um viés cognitivo: o crítico tende a ser mais complacente com o que ele mesmo acabou de produzir. O grafo pesquisador já segue essa recomendação por construção, já que buscar e avaliar são nós distintos, não uma única chamada fazendo as duas coisas. O autor também liga Reflection a memória (cap. 8): sem lembrar as tentativas anteriores do loop, o agente pode repetir a mesma busca malsucedida a cada iteração em vez de tentar uma estratégia diferente.

Perguntas frequentes

PerguntaResposta
"Por que Annotated[list, add_messages] em vez de list simples?"Com list simples, cada update de node substitui a lista inteira, perdendo o historico. Annotated[list, add_messages] usa um reducer que acumula: quando um node retorna {"mensagens": [nova_msg]}, o LangGraph faz merge, adicionando a lista existente. Campos sem reducer (int, str, float) sao sempre substituidos pelo ultimo update.
"MemorySaver em producao e seguro?"Nao — MemorySaver e in-memory e perde tudo ao reiniciar. Para producao usar SqliteSaver (arquivo local) ou PostgresSaver (banco de dados). A API e identica — so troca o checkpointer no compile(). Para CKP e demos, MemorySaver e suficiente.
"draw_mermaid_png() deu erro no Colab — como resolver?"Requer playwright: !pip install playwright && playwright install chromium. Alternativa sem instalacao: usar draw_mermaid() e colar o output em mermaid.live. Renderiza online instantaneamente.
"O grafo pode ter multiplos interrupt_before?"Sim — interrupt_before=["no_A", "no_B"] pausa antes de qualquer um dos dois. Tambem existe interrupt_after — pausa depois do no (o no executa, mas o proximo fica suspenso). Para pipelines com multiplos checkpoints de aprovacao, usar lista de nos.

Demo Prática ao Vivo — agente pesquisador com loop condicional

agente_pesquisador.py
from langgraph.graph import StateGraph, START, END
from langchain_community.tools import DuckDuckGoSearchRun
from pydantic import BaseModel
from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages
from langchain_core.messages import HumanMessage
from langchain_core.prompts import ChatPromptTemplate

class EstadoPesquisa(TypedDict):
    mensagens: Annotated[list, add_messages]
    resultados_busca: str
    qualidade: float
    iteracoes: int

class Qualidade(BaseModel):
    score: float; suficiente: bool

def node_buscar(state) -> dict:
    bruto = DuckDuckGoSearchRun().run(state["mensagens"][0].content)
    return {"resultados_busca":bruto[:1500], "iteracoes":state["iteracoes"]+1}

def node_avaliar(state) -> dict:
    q = (ChatPromptTemplate.from_template(
        "Pergunta:{p}\nResultado:{r}\nScore suficiencia 0.0-1.0:"
    ) | llm.with_structured_output(Qualidade)).invoke(
        {"p":state["mensagens"][0].content, "r":state["resultados_busca"]}
    )
    return {"qualidade": q.score}

def node_responder(state) -> dict:
    resp = llm.invoke([HumanMessage(
        f"Pergunta:{state['mensagens'][0].content}\nFonte:{state['resultados_busca']}"
    )])
    return {"mensagens":[resp]}

def decidir_continuar(state) -> str:
    # Para se qualidade OK ou atingiu limite de 3 iteracoes
    if state["qualidade"] >= 0.7 or state["iteracoes"] >= 3:
        return "responder"
    return "buscar"  # loop de volta

builder = StateGraph(EstadoPesquisa)
builder.add_node("buscar",node_buscar); builder.add_node("avaliar",node_avaliar)
builder.add_node("responder",node_responder)
builder.add_edge(START,"buscar"); builder.add_edge("buscar","avaliar")
builder.add_conditional_edges("avaliar",decidir_continuar,
                              {"buscar":"buscar","responder":"responder"})
builder.add_edge("responder",END)
pesquisador = builder.compile(checkpointer=MemorySaver())

Lab — Aula 13 · 2º Semestre
Grafo pesquisador com loop condicional para o dominio ★★★

Grupo 3–4 · 25 minutos · Google Colab

  1. Complete as 5 lacunas — TypedDict com add_messages + tipos; node_buscar com DuckDuckGo; node_responder usando resultados_busca; decidir_continuar com threshold 0.7 e MAX 3; montar o grafo com add_node, add_edge e add_conditional_edges.
  2. Visualize o grafo com draw_mermaid() — confirmar que a aresta de volta (avaliar → buscar) aparece no diagrama.
  3. Execute 2 perguntas do dominio e observe: quantas iteracoes foram necessarias? O threshold 0.7 foi atingido antes do limite 3 ou precisou do MAX?
  4. Experimento com threshold: mudar para 0.5 e 0.9 e documentar a diferenca no numero de iteracoes em celula markdown.
Gabarito das lacunas
L1: add_messages ; float ; int
L2: state["mensagens"][0].content
L3: state["resultados_busca"]
L4: 0.7 ; 3 ; "responder" ; "buscar"
L5: node_buscar ; node_avaliar ; node_responder ; "avaliar" ; decidir_continuar
Desafio — HITL no pesquisador: adicionar interrupt_before=["responder"] para que o humano aprove antes da resposta final. Testar: o grafo pausa? get_state() mostra o no suspenso? invoke(None) retoma?
