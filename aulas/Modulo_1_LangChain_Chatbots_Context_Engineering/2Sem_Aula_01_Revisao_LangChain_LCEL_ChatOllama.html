Glossário — termos novos de hoje

Conceitos que você vai usar em todas as aulas deste semestre. Definição técnica direta — nada de decoreba:

LangChain /læŋʧeɪn/
Framework Python para orquestrar LLMs: conecta modelo, prompt, memória, RAG e tools em chains (cadeias) composáveis, em vez de código manual repetido.
LCEL
LangChain Expression Language — linguagem declarativa que compõe componentes com o operador | (pipe). A chain descreve o fluxo, não o código que o executa.
Runnable /rʌnəbəl/
Interface padrão que toda chain herda: .invoke(), .stream(), .batch(), .ainvoke(). É o "contrato" único para executar qualquer pipeline.
ChatPromptTemplate
Template de prompt com roles (system/human/ai) e variáveis {var} validadas em runtime — evolução da função montar_prompt() do 1º semestre.
ChatOllama
Integração oficial do LangChain com o Ollama (local ou Cloud): conecta o modelo (gpt-oss:120b) como componente de chat dentro de uma chain.
OutputParser
Componente que transforma a resposta bruta do modelo (AIMessage) em um formato útil para o seu código: texto, dict, ou objeto Pydantic validado.
StrOutputParser
Parser mais simples: extrai apenas o conteúdo textual da resposta. Elimina o resp["message"]["content"] do 1º semestre.
JsonOutputParser
Parser que converte a resposta em dict Python. Exige que o prompt peça JSON explicitamente — sem schema garantido (isso vem na Aula 03 com Pydantic).
chain
Pipeline de componentes encadeados pelo operador |. O output de um componente é o input do próximo.
stateless
Sem estado: cada chamada .invoke() começa do zero, sem lembrar conversas anteriores. A chain de hoje é stateless; memória é a Aula 02.
streaming
Receber a resposta token por token, em tempo real — efeito "digitando" em interfaces. Método .stream(), usado em produção e na Aula 08 com Gradio.
AIMessage
Objeto de resposta do LangChain: contém o texto em .content, além de metadados (uso de tokens, modelo, timestamps).
💼 Por que isso importa no mercado
LangChain é o framework de orquestração de LLMs mais usado em produção — a base de pipelines de geração de código, escrita assistida e automação de workflows em empresas de tecnologia. Domine o vocabulário de hoje (chain, parser, Runnable) e você fala a mesma língua das vagas de AI Engineer em 2026.

Segurança em LLMs — revisão: prompt injection, jailbreak e guardrails

Este bloco recapitula a Aula 10 do 1º semestre (Módulo 3 — Prompt Engineering Avançado: "Prompt Injection, Segurança e Guardrails"). Não é conteúdo novo — é o que garante que a chain LCEL que você vai montar hoje não repita as mesmas vulnerabilidades do system prompt manual do 1º semestre.

⚠️ Ataques que você já viu
Prompt injection direto — o usuário tenta sobrescrever o system prompt na própria mensagem ("ignore as instruções anteriores...").
Prompt injection indireto — instrução maliciosa embutida num dado processado pelo modelo (e-mail, PDF, página web sendo resumida).
Prompt leaking — extrair o system prompt oculto através de perguntas indiretas.
Jailbreaking — roleplay, encoding (Base64) ou personas fictícias para contornar guardrails.
🚨 Por que isso nunca desaparece
LLMs não distinguem instrução do desenvolvedor de instrução do usuário — tudo é texto na mesma context window (janela de contexto). Isso vale igual para o ChatPromptTemplate que você vai construir hoje.
🛡️ Defesa em camadas — as 5 que você já aprendeu
  • System prompt robusto — regras invioláveis + sandwich defense (regras repetidas no início e no fim)
  • Validação de input — bloquear padrões como "ignore", "esqueça", "system prompt"
  • Separação dados↔instruções — delimitadores (crases triplas, tags XML)
  • Validação de output — checar dado sensível vazado antes de responder
  • Monitoramento e logging — kill switch para respostas fora do esperado
🔗 Conexão com a Aula 04 e a Aula 10 deste semestre
Context Engineering (Anthropic, 2025) trata o contexto como recurso finito — quanto mais informação irrelevante no contexto, menos atenção o modelo dá aos guardrails. A Aula 04 aprofunda essa curadoria; a Aula 10 aplica defesa em camadas a agentes com tools.

Técnicas de prompt e Python que você já escreve

Nenhuma dessas habilidades desaparece com LangChain — elas migram para dentro dos componentes da chain.

✅ Técnicas de prompt
Zero-shot · Few-shot · Chain-of-Thought
Role prompting · System prompt com persona
Parâmetros: temperatura, top-p, num_predict
✅ Python que você sabe fazer
def, while True/break, f-string multiline, **dict, retorno múltiplo, continue

Onde essas técnicas vão morar em LCEL

  • Few-shot e CoT viram exemplos dentro do ChatPromptTemplate
  • Role prompting vira a mensagem system do template
  • Parâmetros (temperatura, top-p) viram argumentos do ChatOllama(...)
  • def montar_prompt() vira um ChatPromptTemplate.from_messages([...])
  • while True do loop de chat vira .stream() ou memória gerenciada

Você não está aprendendo prompting do zero — está aprendendo a declarar em LCEL o que já sabia escrever manualmente em Python puro.

O ponto de partida: o chatbot manual do 1º semestre

Este é o código que você já escreveu e que serve de base para tudo que vem hoje. Guarde-o na cabeça — o próximo bloco reescreve exatamente isto em LCEL.

python — chatbot manual do 1º semestre (~40 linhas, resumido)
def montar_prompt(historico, pergunta):
    return [{"role": "system", "content": SYSTEM_PROMPT}] \
        + historico + [{"role": "user", "content": pergunta}]

def chamar_llm(messages):
    resp = ollama.chat(model="gpt-oss:120b", messages=messages)
    return resp["message"]["content"]

def iniciar_chat():
    historico = []
    while True:
        pergunta = input("Você: ")
        if pergunta == "sair": break
        msgs = montar_prompt(historico, pergunta)
        resposta = chamar_llm(msgs)
        historico += [{"role": "user", "content": pergunta},
                     {"role": "assistant", "content": resposta}]
        print("Bot:", resposta)
✅ Chatbot manual — o que ele já faz
chamar_llm() → iniciar_chat() → montar_prompt() · lista messages com 3 roles · histórico gerenciado manualmente em cada volta do loop.
🔗 O ponto de partida desta aula
Três funções, gerenciamento manual de historico, acesso direto a resp["message"]["content"]. Funciona — mas não escala, não compõe e não tem memória além do que você programar à mão. Esse chatbot manual (~40 linhas) é o problema que o LangChain resolve: hoje você reescreve isso em 15 linhas usando LCEL.

O LCEL usa o operador | (pipe) para compor componentes. O output de um vira input do próximo:

|

|

Workflow de uma chain LCEL — clique em cada bloco para ver o que acontece internamente. O | é a "esteira" que conecta os estágios.
lcel_basico.py
from langchain_ollama import ChatOllama
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# Cada componente é independente — compostos pelo operador |

# 1. Template: define estrutura e variáveis do prompt
prompt = ChatPromptTemplate.from_messages([
    ("system", "Você é {persona}. Responda sobre {especialidade}."),
    ("human",  "{pergunta}"),
])

# 2. Modelo: conecta ao Ollama Cloud
llm = ChatOllama(
    model="gpt-oss:120b",
    base_url="https://ollama.com",
)

# 3. Parser: extrai só o texto da resposta
parser = StrOutputParser()

# Composição com |  — isso é uma Runnable, não uma chamada
chain = prompt | llm | parser

# Invocar a chain com as variáveis do template
resposta = chain.invoke({
    "persona":       "um chef de culinária brasileira",
    "especialidade": "culinária brasileira",
    "pergunta":      "Como faço um bolo de cenoura?",
})
print(resposta)  # → string direta, sem resp["message"]["content"]

ChatPromptTemplate — evolução do montar_prompt()

ChatPromptTemplate substitui a função montar_prompt() que você escreveu no 1º semestre — com validação automática de variáveis:

🔙 1º semestre — f-string manual
def montar_prompt(pergunta,
                    especialidade,
                    tom="direto"):
    return f"""
Você é especialista em {especialidade}.
Pergunta: {pergunta}
Tom: {tom}.
"""

# Problema: f-string não valida variáveis
# se esquecer uma, silencia sem erro
🔮 2º semestre — ChatPromptTemplate
prompt = ChatPromptTemplate.from_messages([
    ("system",
     "Você é especialista em {especialidade}."
     " Tom: {tom}."),
    ("human", "Pergunta: {pergunta}"),
])

# Vantagem: valida variáveis automaticamente
# KeyError se esquecer alguma ao invocar
# Separação de roles limpa (system/human/ai)
💡 from_messages vs. from_template
from_messages([("system","..."), ("human","...")]) — quando você precisa de roles diferentes (a maioria dos casos com LLMs de chat).
from_template("texto simples com {var}") — para prompts de texto puro, sem roles.

Output Parsers — StrOutputParser e JsonOutputParser

O parser define como o output do modelo é transformado antes de chegar ao seu código:

StrOutputParser — texto limpo
from langchain_core.output_parsers import StrOutputParser

chain = prompt | llm | StrOutputParser()

# Retorna string direta
resposta = chain.invoke({"pergunta":"Oi"})
print(type(resposta))  # → <class 'str'>

# Sem mais resp["message"]["content"] !
JsonOutputParser — dict direto
from langchain_core.output_parsers import JsonOutputParser

chain = prompt | llm | JsonOutputParser()

# O prompt DEVE pedir JSON explicitamente
resultado = chain.invoke({
    "pergunta": "Liste 3 ingredientes"
})
print(type(resultado))   # → <class 'dict'>
print(resultado["ingredientes"])
⚠️ JsonOutputParser sem schema = risco
O JsonOutputParser tenta parsear qualquer JSON que o modelo gere — mas não garante que as chaves esperadas existam. Na Aula 03 você vai usar PydanticOutputParser, que valida o schema e levanta erro se a saída não bater.

ChatOllama — conectando ao Ollama Cloud

No 1º semestre você usou ollama.Client(host=..., headers={...}). No LangChain, o setup é declarativo:

setup_ollama_cloud.py

from langchain_ollama import ChatOllama
from google.colab import userdata
import os

# Definir a API key via variável de ambiente (Colab Secrets)
os.environ["OLLAMA_HOST"]    = "https://ollama.com"
os.environ["OLLAMA_API_KEY"] = userdata.get("OLLAMA_API_KEY")

# Instanciar o modelo — parâmetros declarativos
llm = ChatOllama(
    model="gpt-oss:120b",          # modelo padrão do semestre
    temperature=0.7,               # mesmo parâmetro do 1º sem
    num_predict=512,               # equivalente a max_tokens
)

# Teste rápido direto (sem chain)
resp = llm.invoke("Olá! Responda em 1 linha.")
print(resp.content)   # .content — não ["message"]["content"]
print(type(resp))      # → AIMessage (objeto LangChain)
✅ Diferença chave: resposta direta vs. chain
llm.invoke("texto") → retorna um AIMessage — precisa de .content para acessar o texto.
chain.invoke({...}) com StrOutputParser → retorna str diretamente. Use chains na maioria dos casos.

Runnable — o que toda chain herda

Qualquer componente LCEL implementa a interface Runnable. Isso dá 4 métodos gratuitos:

.invoke()
Chama a chain com 1 input e retorna 1 output. O método mais usado.
chain.invoke({"pergunta": "..."})
.stream()
Retorna generator — tokens chegam um a um. Usado em interfaces para efeito "digitando".
for chunk in chain.stream({...}): print(chunk, end="")
.batch()
Processa lista de inputs em paralelo. Útil para avaliar prompts com múltiplos casos de teste.
chain.batch([{"q":"A"}, {"q":"B"}])
.ainvoke()
Versão assíncrona de invoke. Usado em servidores web (FastAPI, Gradio) para não bloquear.
await chain.ainvoke({...})
🎯 Regra prática para o semestre
Use .invoke() em notebooks e testes. Use .stream() na Aula 08 quando você adicionar interface Gradio. Use .batch() para avaliar seu RAG na Aula 07.

LangChain no mercado — padrões de produção com LCEL

Os mesmos 3 componentes de hoje (prompt · modelo · parser) aparecem, com variações, em categorias inteiras de produtos de IA:

Assistentes de código
LangChain orquestrando múltiplos LLMs
Ferramentas de código assistido orquestram chains de geração e revisão — o modelo gerador e o modelo revisor são componentes diferentes numa mesma pipeline LCEL. Você vai construir algo similar na Aula 12 com LangGraph.
Escrita assistida
ChatPromptTemplate por contexto
Templates de prompt diferentes por tipo de tarefa (resumo, expansão, brainstorm) — cada um com variáveis que recebem o conteúdo do documento atual. É exatamente o padrão que você aprendeu hoje com ChatPromptTemplate.
Automação de workflows
Chains como nós de workflow
Plataformas de automação (RPA + IA) usam LangChain por baixo — cada ação automatizada é uma chain que recebe contexto do usuário, chama o LLM e retorna output estruturado para o próximo passo do workflow. OutputParser com Pydantic garante que os dados chegam no formato certo.
Automação de processos (BPM)
Triagem e resposta padronizada
Plataformas de BPM com IA usam LangChain para automatizar triagem de tickets e geração de respostas padronizadas — ChatPromptTemplate por tipo de solicitação, JsonOutputParser para routing automático.

Perguntas frequentes

PerguntaResposta
"Preciso desinstalar o pacote ollama do 1º semestre?"Não — eles coexistem sem conflito. ollama (cliente original) e langchain-ollama (integração LangChain) são pacotes diferentes. Você pode ter os dois instalados simultaneamente.
"O | é o operador OR do Python?"Em Python puro, | é OR bitwise e union de dicts (Python 3.9+). No LangChain, a classe Runnable sobrescreve o método __or__ para retornar uma chain composta em vez de OR.
"Por que usar ChatPromptTemplate se f-string também funciona?"Para projetos simples, f-string funciona. A vantagem do template aparece na escala: validação de variáveis em tempo de execução, reutilização com valores diferentes, integração automática com chains mais complexas (memória, RAG, agentes).
"Preciso de conta no LangSmith para usar LangChain?"Não — LangSmith é a plataforma de rastreamento (opcional). Todo o código do semestre roda sem LangSmith. Se quiser ativar, é gratuito para uso pessoal e adiciona observabilidade automática.
"A versão do LangChain importa?"Muito — o LangChain teve mudanças de API significativas entre versões. O semestre usa LangChain 0.3+ (LCEL estável). Sempre instale com pip install langchain-core langchain-ollama para pegar a versão atual.
"Posso usar outros modelos além de gpt-oss:120b?"Sim — o semestre usa gpt-oss:120b como padrão, mas qualquer modelo disponível no Ollama Cloud funciona. Outros modelos como llama4:scout ou deepseek-r2 também funcionam bem, dependendo da tarefa.
"LCEL vai mudar? Vale aprender agora?"LCEL foi estabilizado na versão 0.3 e é a API de longo prazo do LangChain. O padrão prompt | llm | parser é o que a documentação oficial recomenda e o que toda a comunidade adotou.

# 1. Instância declarativa com keyword arguments
llm = ChatOllama(model="gpt-oss:120b", temperature=0.7)

# 2. Método de classe com lista de tuplas
prompt = ChatPromptTemplate.from_messages([
    ("system", "Você é {persona}."),
    ("human",  "{pergunta}"),
])

# 3. Operator overloading — | cria chain composta
chain = prompt | llm | StrOutputParser()

# 4. .invoke() — método com dict de variáveis
resp = chain.invoke({"persona": "chef", "pergunta": "Olá"})

# 5. Generator com for + yield (em .stream())
for chunk in chain.stream({"pergunta": "Oi"}):
    print(chunk, end="", flush=True)
    # flush=True força exibição imediata de cada token

  3. Teste com 3 perguntas do domínio — confirme que a persona está coerente com o domínio escolhido.
  4. Desafio — JsonOutputParser: crie uma segunda chain com JsonOutputParser. No prompt, peça ao modelo para responder em JSON com as chaves resposta e confianca (0–10). Imprima o tipo do resultado.
🎯 Orientação das lacunas
Lacuna 1: nome do modelo do semestre e a temperatura usada desde o 1º semestre (0.7).
Lacuna 2: a role de sistema recebe a persona e o domínio do grupo; a role humana recebe a variável da pergunta.
Lacuna 3: os 3 componentes na ordem prompt → modelo → parser, unidos pelo operador pipe.
Lacuna 4: qualquer pergunta real do domínio escolhido pelo grupo.
💡 Dica para o desafio: no prompt, adicione: "Responda SOMENTE em JSON no formato: {\"resposta\": \"...\", \"confianca\": N}". O modelo precisa da instrução explícita para gerar JSON válido.
