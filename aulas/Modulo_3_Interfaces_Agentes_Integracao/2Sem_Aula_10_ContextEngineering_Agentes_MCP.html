Glossário

Scratchpad
Espaço de memória de trabalho onde o agente anota resultados intermediários, planos e observações durante o loop — bloco de notas temporário, descartado ou resumido ao fim da tarefa.
Memória episódica
Registro persistente de execuções passadas do agente entre sessões distintas — permite lembrar decisões e resultados de tarefas anteriores, diferente da memória de curto prazo que vive só dentro do loop atual.
Princípio da ação mínima
Regra de design que prioriza reduzir tokens gastos por ação do agente (chamada de tool, observação) mantendo o mesmo resultado — cada token economizado por turno se multiplica ao longo de loops longos.
Compressão de observations
Técnica de resumir o retorno de uma tool antes de inserir no contexto do agente — evita que uma observação verbosa (ex.: HTML bruto de uma página) consuma o context window inteiro.
Janela deslizante (sliding window)
Estratégia que mantém apenas as N interações mais recentes do loop agêntico no contexto, descartando as mais antigas — garante custo de tokens constante em vez de crescer a cada turno.
MCP (Model Context Protocol)
Protocolo aberto que padroniza como agentes se conectam a tools e fontes de dados externas — permite trocar de cliente ou servidor sem reescrever a integração.
MCP client / MCP server
Arquitetura do MCP: o servidor expõe tools, resources e prompts; o cliente (o agente) descobre e chama essas capacidades via protocolo comum, sem acoplamento direto ao código do servidor.
Context rot em loop agêntico
Degradação de qualidade das respostas do agente conforme o número de turnos cresce e o contexto acumula ruído — medido comparando qualidade da decisão no turno 1 vs. turno N.

Por que o loop cria um problema de contexto novo

Na Aula 04 (Context Engineering), o sistema prompt tinha ~10% do contexto. Em agentes, o loop gera scratchpad que cresce a cada iteração:

Chat / RAG (Módulos 1–2)
system (~10%) + contexto RAG (~50%) + histórico (~30%) + input (~10%)

Previsível. Controlado. A cada chamada, o desenvolvedor escolhe o que entra.
Agente em loop (a partir da Aula 09)
system + tools_schema + scratchpad_t1 + scratchpad_t2 + ... + scratchpad_tN + input

O scratchpad cresce a cada iteração. Em 10 loops com resultados de busca ricos, o contexto pode ultrapassar 32k tokens — e o context rot degrada o raciocínio.

3 tipos de memória agêntica — quando usar cada um

Tipo 1
In-context
(Scratchpad)
O Thought/Action/Observation de cada iteração do loop. Vai diretamente no contexto da próxima chamada ao LLM. Rápido mas finito e caro.
Uso: raciocínio corrente (esta sessão)
Tipo 2
External
(ChromaDB)
Documentos do domínio indexados como embeddings. O agente busca quando precisa — não carrega tudo no contexto. Ilimitado e econômico.
Uso: base de conhecimento do domínio
Tipo 3
Episódica
(Histórico)
Resumo das sessões anteriores salvo no ChromaDB ou arquivo. O agente recupera contexto relevante de interações passadas. Persistente entre sessões.
Uso: personalização e continuidade
💡 Analogia com a arquitetura de computadores (Russell & Norvig, 2016)
Scratchpad = RAM (rápido, volátil, finito). ChromaDB externo = HD (persistente, barato, requer busca). Memória episódica = cache de sessão (seleciona o mais relevante para carregar na RAM). Um agente bem projetado minimiza o uso de RAM e maximiza a eficiência de busca no HD.

Scratchpad — o contexto de trabalho do agente

O scratchpad é a "área de rascunho" do agente: acumula cada Thought, Action e Observation da sessão corrente. Com verbose=True você já o viu — aqui está sua anatomia:

scratchpad_anatomia.py
# O que o AgentExecutor mantém internamente como scratchpad
scratchpad_turno_1 = """
Thought: Preciso buscar o prazo de garantia nos documentos.
Action: buscar_nos_documentos
Action Input: "prazo de garantia"
Observation: [manual.pdf, pág.15] O prazo de garantia é de 24 meses...
"""  # ~80 tokens

scratchpad_turno_2 = """
Thought: Encontrei 24 meses. Vou converter para dias.
Action: calcular
Action Input: "24 * 30"
Observation: 720
"""  # +40 tokens → total: ~120 tokens

# Após 10 iterações com resultados de busca ricos:
# scratchpad ≈ 10 × 800 chars ≈ ~2.000 tokens só de Observations
# + Thoughts (~500 tokens) + system + tools_schema (~1.000 tokens)
# Total: ~3.500–5.000 tokens por invocação do agente

# Inspecionar o scratchpad via intermediate_steps
resultado = executor.invoke({"input": "pergunta"})
for i, (action, obs) in enumerate(resultado["intermediate_steps"], 1):
    print(f"Iteração {i}: tool={action.tool}, obs_len={len(str(obs))} chars")
# → Iteração 1: tool=buscar_nos_documentos, obs_len=842 chars
# → Iteração 2: tool=calcular, obs_len=3 chars
📖 Fundamentação — janela de contexto longa não é memória de longo prazo
Gullí (Agentic Design Patterns, O'Reilly, 2025, cap. 8 — Memory Management) distingue memória de agente em duas categorias fundamentais: Short-Term/Contextual — o que cabe na janela de contexto, existe só durante a chamada atual — e Long-Term/Persistent — armazenada fora do processo do agente e recuperada por busca semântica quando necessário. O ponto do autor que vale reforçar aqui: um modelo com janela de contexto maior não substitui memória de longo prazo, ele só aumenta o tamanho do scratchpad acima — que continua efêmero e caro de reprocessar a cada chamada, como os ~3.500–5.000 tokens por invocação que você acabou de ver. É por isso que os Tipos 2 e 3 do slide anterior (ChromaDB externo e memória episódica) existem mesmo em modelos com contexto grande: não é economia de espaço, é persistência real entre sessões.

Princípio da ação mínima — menos tokens, mesmo resultado

Cada token no scratchpad é custo de processamento e risco de context rot. O princípio da ação mínima diz: fazer o mínimo necessário para avançar na tarefa:

Anti-padrãoPadrão mínimoEconomia de tokens
Buscar 10 chunks no RAG quando 3 bastam as_retriever(search_kwargs={"k": 3}) ~70% dos tokens de Observation
Retornar o texto completo da busca web (500+ chars) Resumir a Observation antes de inserir no scratchpad ~60% dos tokens de Observation
Manter todas as iterações anteriores no scratchpad Janela deslizante: manter apenas as últimas N iterações Custo fixo independente do número de turnos
System prompt com 500 tokens de instruções genéricas System prompt XML taggeado e compactado (Aula 04) 40–60% do system prompt
📖 Anthropic Context Engineering for AI Agents (set/2025)
"Agents should do the minimum necessary work to accomplish the task. Every unnecessary token in the scratchpad is a tax on reasoning quality in future steps." A ação mínima não é preguiça — é engenharia de qualidade.

Compressão de Observations — resumir antes de inserir

A maior fonte de tokens no scratchpad são as Observations (resultados das tools). Uma tool wrapper que resume antes de retornar reduz drasticamente o scratchpad:

tool_compressao.py
# Tool wrapper que comprime a Observation antes de retornar ao scratchpad
from langchain_core.tools import tool
from langchain_ollama import ChatOllama
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

llm_mini = ChatOllama(model="gpt-oss:120b", temperature=0)

chain_resumir = (
    ChatPromptTemplate.from_template(
        "Resuma o texto abaixo em no máximo 3 frases, mantendo APENAS os fatos essenciais:\n\n{texto}"
    )
    | llm_mini | StrOutputParser()
)

@tool
def buscar_na_web_comprimida(query: str) -> str:
    """Use para buscar informações atuais na web. Retorna um resumo conciso dos resultados."""
    resultado_bruto = DuckDuckGoSearchRun().run(query)

    # Comprime ANTES de retornar ao scratchpad
    if len(resultado_bruto) > 500:
        return chain_resumir.invoke({"texto": resultado_bruto})
    return resultado_bruto  # já curto — não precisa resumir

# Diferença típica:
# Sem compressão: Observation = 800–1200 chars (~250 tokens)
# Com compressão: Observation = 150–250 chars (~55 tokens)
# Redução: ~78% dos tokens de Observation

Janela deslizante — custo fixo em loops longos

Em vez de acumular todo o scratchpad, manter apenas as últimas N iterações garante custo fixo independente da duração do loop:

janela_deslizante.py
from langchain.agents import AgentExecutor, create_react_agent
from langchain_core.messages import trim_messages

# Estratégia 1 — limitar via max_iterations (simples)
executor_limitado = AgentExecutor(
    agent=agente,
    tools=tools,
    max_iterations=5,       # mantém no máximo 5 iterações no scratchpad
    max_execution_time=60,  # para após 60 segundos (fallback de segurança)
    verbose=True,
)

# Estratégia 2 — resumo episódico entre turnos (avançado)
def resumir_scratchpad(intermediate_steps: list, max_steps: int = 3) -> list:
    """Mantém as últimas max_steps iterações e resume o resto."""
    if len(intermediate_steps) <= max_steps:
        return intermediate_steps

    antigas   = intermediate_steps[:-max_steps]
    recentes  = intermediate_steps[-max_steps:]

    # Resumir as iterações antigas em uma linha
    resumo = ", ".join(f"{a.tool}→{str(o)[:50]}" for a,o in antigas)
    print(f"[Resumo de {len(antigas)} iterações anteriores: {resumo}]")

    # Retorna só as recentes — scratchpad compacto
    return recentes
⚡ max_execution_time — o seguro de prazo
Em produção, além de max_iterations, defina max_execution_time em segundos. Um agente travado em uma tool que não responde não vai loop infinito — vai parar após o timeout e retornar o que tem. Para o CKP03, max_iterations=5 e max_execution_time=120 são boas práticas.

Memória episódica — persistir entre sessões

O scratchpad some quando a sessão termina. Memória episódica salva o resumo da sessão no ChromaDB para recuperar contexto relevante em sessões futuras:

memoria_episodica.py
from langchain_community.vectorstores import Chroma
from langchain_core.documents import Document
from datetime import datetime

# Salvar resumo da sessão ao encerrar
def salvar_sessao(pergunta: str, resposta: str, session_id: str):
    """Persiste o par (pergunta, resposta) como memória episódica."""
    db_episodico.add_documents([Document(
        page_content=f"Pergunta: {pergunta}\nResposta: {resposta}",
        metadata={
            "session_id": session_id,
            "timestamp": datetime.now().isoformat(),
            "tipo": "episodio",
        },
    )])

# Recuperar contexto de sessões anteriores (memória episódica como tool)
@tool
def lembrar_sessoes_anteriores(query: str) -> str:
    """Use quando o usuário se referir a algo discutido em conversa anterior.
    Retorna resumos de interações passadas relevantes para a query."""
    docs = db_episodico.similarity_search(query, k=2,
                                          filter={"tipo": "episodio"})
    return "\n\n".join(d.page_content for d in docs)

MCP — Model Context Protocol

Criado pela Anthropic em novembro de 2024, o MCP padroniza como agentes de IA se conectam a ferramentas e fontes de dados externas:

❌ Antes do MCP — N×M integrações
Cada agente precisava de código customizado para integrar com cada ferramenta. 5 agentes × 10 ferramentas = 50 integrações diferentes para manter. Mudança na API de uma ferramenta quebra todos os agentes.
✅ Com MCP — N+M integrações
Cada ferramenta expõe um servidor MCP. Cada agente é um cliente MCP. 5 agentes + 10 ferramentas = 15 implementações. Adicionar uma nova ferramenta não requer mudar os agentes.
Arquitetura MCP
MCP Host (Claude, Cursor, seu agente) — executa as requests
⇅ JSON-RPC 2.0
MCP Server (sua ferramenta) — expõe tools, resources, prompts
⇅ HTTP / SSE / stdio
Data Source (BD, API, arquivo, ChromaDB)
Protocolo aberto · Suportado por Anthropic, OpenAI, Google, Microsoft, Cursor, n8n, e 3000+ ferramentas
📖 Fundamentação — Quando vale a pena usar MCP (e o custo de segurança)
Polzer (RAG with Python Cookbook, O'Reilly, 2026) reforça a analogia desta aula com uma comparação direta: o MCP funciona para ferramentas de agente como o HTTP funciona para navegadores — um protocolo comum que evita integração sob medida a cada combinação de agente e ferramenta. Mas o autor também marca o limite dessa vantagem: para um agente simples e de propósito único, com tools fortemente acopladas à própria lógica do agente, a camada extra do protocolo não compensa — o ganho de reuso só aparece quando várias equipes ou frameworks precisam compartilhar a mesma ferramenta. Há ainda um custo de segurança que esta aula não cobriu até aqui: cada MCP Server aceita requisições de rede, então expande a superfície de ataque do sistema e exige autenticação, autorização e validação de input próprios — diferente de uma function call local, que roda no mesmo processo confiável do agente.

from langchain_mcp_adapters.tools import load_mcp_tools
from mcp import ClientSession
from mcp.client.stdio import stdio_client

# Conectar a um servidor MCP local (ex: servidor de filesystem)
async def conectar_mcp():
    async with stdio_client(
        {"command": "npx", "args": ["@modelcontextprotocol/server-filesystem", "/content"]}
    ) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            # Carrega tools do servidor MCP como tools LangChain
            mcp_tools = await load_mcp_tools(session)
            # → lista de ferramentas prontas para o AgentExecutor
            return mcp_tools

# Servidores MCP gratuitos disponíveis hoje:
# @modelcontextprotocol/server-filesystem  — ler/escrever arquivos
# @modelcontextprotocol/server-brave-search — busca web
# mcp-server-fetch                          — fazer requisições HTTP
# mcp-server-sqlite                         — consultar SQLite
# Catálogo: github.com/modelcontextprotocol/servers

Perguntas frequentes

PerguntaResposta
"Comprimir a Observation não perde informação importante?"Potencialmente sim — por isso a compressão deve ser contextual, não genérica. O resumo de 3 frases mantém os fatos essenciais para o raciocínio. Para casos críticos (documentos jurídicos, laudos), considere comprimir só as Observations de web search e manter integrais as do RAG (que já são chunks pequenos).
"Por que o MCP usa JSON-RPC e não REST?"JSON-RPC é bidirecional — permite que o servidor notifique o cliente de eventos assíncronos (ex: atualização de dados). REST é request-response unidirecional. Para agentes que precisam reagir a eventos externos em tempo real, a bidirecionalidade do JSON-RPC é essencial. Além disso, JSON-RPC tem overhead menor que REST para chamadas frequentes de tools.
"Memória episódica vs. ConversationBufferMemory — qual a diferença?"ConversationBufferMemory (Aula 02) mantém o histórico da conversa corrente no contexto. Memória episódica mantém um banco de sessões passadas no ChromaDB — persistente entre reinicializações. Para um agente comercial, você usaria ambas: buffer para a sessão atual + episódica para personalização entre sessões de dias diferentes.

plt.bar([i+width/2 for i in x], vals_b, width, label="B")  # deslocado +0.2

# 5. statistics.mean() para calcular redução média
import statistics
reducao_pct = (1 - statistics.mean(tok_com) / statistics.mean(tok_sem)) * 100
print(f"Redução média: {reducao_pct:.1f}%")

Context engineering para agentes em produção

Agentes de visão de tela
Screenshots como memória
Agentes que operam por captura de tela veem cada passo como imagem (Observation). Para não acumular dezenas de screenshots no contexto, extraem apenas texto relevante antes de inserir no scratchpad — compressão visual de Observations.
IDEs com agente embutido
MCP para contexto de código
IDEs com agente de código embutido usam MCP para conectar o agente ao repositório, ao terminal e ao rastreador de issues. Cada ferramenta é um servidor MCP independente — o agente decide qual usar baseado na tarefa, sem acumular o repositório inteiro no contexto.
Plataformas no-code de agentes
Memória externa no nó
Plataformas no-code de automação oferecem nó nativo de memória vetorial (bancos como Pinecone, Qdrant, pgvector). O agente recupera contexto de execuções anteriores a partir dessa memória externa — o mesmo padrão episódico desta aula, aplicado a workflows no-code.
