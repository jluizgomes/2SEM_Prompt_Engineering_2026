# Título Conteúdo · Demo · Lab
01📅 03/08
Revisão expressa + LangChain LCEL e ChatOllama
Revisão 20min 🐍 LangChain
Revisão expressa do 1º semestre em 20 min: mapa de conceitos, o chatbot do CKP03 como ponto de partida. Por que usar LangChain: o problema de orquestrar chamadas manualmente em produção. LCEL — o operador | como composição: prompt | llm | parser. ChatOllama conectado ao Ollama Cloud. ChatPromptTemplate com variáveis. StrOutputParser e JsonOutputParser.

Demo ao vivo: reescrever o chatbot do 1º semestre em LangChain — antes: 40 linhas manuais; depois: 15 linhas LCEL. O aluno vê o mesmo comportamento com menos código.

Lab (Notebook Aluno, 40% lacunas): construir a chain básica — escolher o domínio do grupo que será usado no semestre inteiro.
3 conceitos: LCEL · ChatPromptTemplate · Output Parser · Conexão 1º sem: substitui o chamar_llm() manual por pipeline declarativo
02📅 10/08
Memória conversacional — Buffer, Summary e TokenBuffer
Teoria 🐍 LangChain
Por que a lista messages do 1º semestre não escala: custo de tokens cresce sem limite. Os 3 tipos de memória: ConversationBufferMemory (tudo na janela), ConversationSummaryMemory (resumo automático), ConversationTokenBufferMemory (limite por tokens). Quando usar cada um. ConversationChain com LangChain integrando os tipos de memória.

Demo ao vivo: conversa longa (15+ turnos) com cada tipo de memória — o aluno vê o custo crescer com Buffer e estabilizar com Summary. Comparar a qualidade da resposta após 20 turnos.

Lab (45% lacunas): chatbot do domínio do grupo com tipo de memória a escolher — justificar a escolha no notebook.
3 conceitos: ConversationBufferMemory · ConversationSummaryMemory · Context window cost · Conexão 1º sem: a lista messages manual agora tem gestão automática
03📅 17/08
Structured output e Pydantic v2
Teoria 🐍 Python
Por que forçar estrutura na saída: o LLM em produção precisa retornar JSON que outro sistema vai consumir — string livre quebra tudo. JSON Schema nativo no Ollama (format="json"). PydanticOutputParser: definir o schema com BaseModel, validar com model_validate(), tratar ValidationError. Casos de uso: extrator de entidades, gerador de relatórios, classificador de tickets.

Demo ao vivo: extrator de informações de currículos — envia texto livre, recebe JSON com nome, habilidades e experiência validados pelo Pydantic.

Lab (50% lacunas): definir o schema Pydantic para o domínio do grupo e integrar à chain existente.
3 conceitos: Structured output · BaseModel (Pydantic) · ValidationError · Conexão 1º sem: as f-strings de template agora têm saída validada
04📅 24/08
Context Engineering — de prompt engineering para context engineering
Teoria 🐍 Python CKP01
A evolução: prompt engineering → context engineering (Anthropic, 2025). Context como recurso finito — cada token tem custo. "Context rot": como o desempenho degrada com contextos longos. O que vai no contexto: system + tools + dados + histórico. XML tagging para estruturar seções. Context caching. Meta prompting: o modelo que melhora seus próprios prompts.

Demo ao vivo: medir degradação de qualidade com contexto crescente — mesmo prompt, mesmo modelo, janelas de 500/3k/10k tokens. O gráfico de qualidade vs. tokens é a conclusão.

Lab (50% lacunas): refatorar o chatbot do grupo aplicando context engineering — medir tokens antes e depois.
3 conceitos: Context Engineering · Context rot · XML tagging · Fonte: Anthropic "Effective Context Engineering for AI Agents" (set/2025)

# Título Conteúdo · Demo · Lab
05📅 31/08
Embeddings e busca semântica com ChromaDB
Teoria 🐍 Python
O que é um embedding: vetor de números que representa significado — a intuição geométrica. nomic-embed-text via Ollama Cloud: 274M parâmetros, janela de 8k tokens, sem custo. Similaridade cosseno: como o sistema encontra documentos relevantes sem palavra-chave. ChromaDB: add(), query(), persist(), metadata filtering. OllamaEmbeddings no LangChain. Comparar busca semântica vs. keyword na mesma coleção.

Demo ao vivo: indexar 20 frases sobre temas variados → buscar por "comida italiana" e ver retornar "pizza", "macarrão" e "lasanha" mesmo sem a palavra "comida".

Lab (45% lacunas): criar coleção ChromaDB com textos do domínio do grupo, testar 5 queries e documentar a qualidade dos resultados.
3 conceitos: Embedding · Similaridade cosseno · ChromaDB · Stack: nomic-embed-text via Ollama Cloud (sem HuggingFace)
06📅 14/09
Pipeline RAG completo — load, split, embed, retrieve, generate
Teoria 🐍 Python
RAG = Retrieval-Augmented Generation: o LLM não precisa saber tudo se consegue buscar. As 6 etapas: (1) carregar PDFs com PyMuPDF, (2) dividir em chunks com RecursiveCharacterTextSplitter, (3) gerar embeddings com nomic, (4) armazenar no ChromaDB, (5) recuperar os top-k mais relevantes, (6) gerar com Qwen3.6 citando as fontes. create_retrieval_chain no LangChain. Qual tamanho de chunk usar e por quê.

Demo ao vivo: RAG sobre 3 PDFs fornecidos em sala — perguntas respondidas com citação de página e trecho. Comparar resposta do modelo sem RAG (alucina) vs. com RAG (responde com fonte).

Lab (50% lacunas): RAG sobre documentos do domínio do grupo — qualquer PDF que o grupo trouxer ao Colab.
3 conceitos: Chunking · Retrieval · Grounding · Resultado: pipeline RAG funcional em ~50 linhas
07📅 21/09
RAG avançado — chunking estratégico, reranking e RAGAS
Teoria 🐍 Python CKP02
Por que chunk_size importa: muito grande perde precisão, muito pequeno perde contexto. Estratégias: RecursiveCharacterTextSplitter (padrão), SemanticChunker (por significado), Parent-Document Retriever (chunk pequeno para busca, chunk grande para contexto). Reranking com cross-encoder. RAGAS: faithfulness (a resposta está nos docs?), answer_relevancy (respondeu a pergunta?), context_precision (recuperou os docs certos?). LLM-as-judge.

Demo ao vivo: mesmo RAG da Aula 06 testado com chunk_size 256, 512 e 1024 — medir RAGAS e mostrar qual ganhou e por quê.

Lab (55% lacunas): otimizar o RAG do grupo com 2 estratégias de chunking + calcular RAGAS básico e documentar qual configuração foi melhor.
3 conceitos: Chunking estratégico · Reranking · RAGAS (faithfulness, answer_relevancy) · Ferramentas: ragas · cross-encoder
📊 Check-in intermediário — Aula 07 · QR Code no slide · 2 perguntas anônimas · resultados lidos ao vivo na Aula 08
🏁
CKP02 — "DocMind RAG" · Grupo 3–4 · Entrega Aula 07 · Obrigatório

09📅 05/10
Agentes de IA — ReAct, tools e function calling
Teoria 🐍 Agentes
O que diferencia um agente de um chatbot: o loop percepção → raciocínio → ação → observação. AI Workflow vs. AI Agent — quando usar cada um. ReAct pattern: Reasoning + Acting. Tool schema: name, description (onde 80% do trabalho está), parameters. Function calling nativo no Qwen3.6. @tool decorator. AgentExecutor: max_iterations, verbose=True. Tools prontas: DuckDuckGoSearchRun, PythonREPLTool, calculadora.

10📅 19/10
Context Engineering para agentes — curadoria em loop agêntico
Teoria 🐍 Python
Context em agentes ≠ context em chat: o loop gera dados continuamente. Tipos de memória agêntica: in-context (scratchpad), external (ChromaDB), episódica (histórico de interações passadas). Curadoria dinâmica: o que incluir e descartar a cada iteração. "Context rot" em loops longos — medir degradação em 5/10/20 turnos ao vivo. Princípio da ação mínima. Model Context Protocol (MCP): overview do padrão para conectar agentes a ferramentas externas.

Demo ao vivo: instrumentar o agente da Aula 09 para medir qualidade da resposta a cada turno. O gráfico de qualidade vs. turnos mostra o context rot acontecendo.

Lab (55% lacunas): implementar estratégia de compressão do scratchpad e medir a diferença.
3 conceitos: Scratchpad agêntico · Context rot em loop · MCP overview · Fonte: Anthropic Context Engineering for AI Agents (set/2025)

# Título Conteúdo · Demo · Lab
12📅 09/11
Router chains e o conceito de grafo de estado
Teoria 🐍 LangChain
Por que chains lineares não são suficientes para sistemas complexos: quando o fluxo precisa de branches e loops. Router Chain: decidir qual chain usar com base no input. Motivação para LangGraph: AgentExecutor é para loops simples; LangGraph é para quando o fluxo tem branches, paralelismo e checkpointing. Introdução ao conceito de StateGraph sem código ainda — apenas o modelo mental.

Demo ao vivo: Router Chain que classifica a intenção do usuário e roteia para 3 handlers diferentes (RAG, cálculo, conversa). O aluno vê o modelo decidindo qual rota seguir.

Lab (50% lacunas): router chain com 3 rotas para o domínio do grupo — o aluno escreve o classificador de intenção e os handlers.
3 conceitos: Router Chain · Grafo de estado (conceitual) · Classificador de intenção · Preparação: o modelo mental de grafo que será implementado na Aula 13
13📅 16/11
LangGraph — StateGraph, nodes, edges, conditional routing e HITL
Teoria 🐍 LangGraph
StateGraph com TypedDict: o estado compartilhado entre todos os nodes. add_node() e add_edge(): nós e arestas. add_conditional_edges(): o ponto onde o grafo decide o próximo passo. MemorySaver checkpointing: salvar e retomar estado entre chamadas. Human-in-the-loop com interrupt_before: pausar para aprovação humana antes de ação irreversível. draw_mermaid() para visualizar o grafo. Devstral-Small como modelo para coding agents.

Demo ao vivo: agente pesquisador com loop condicional — node de busca → node de avaliação → conditional edge (buscar mais ou responder) → node de resposta. Máximo 3 iterações. Visualizar o grafo com draw_mermaid().

Lab (60% lacunas): construir o mesmo agente pesquisador para o domínio do grupo. O grafo deve ter pelo menos 3 nodes e 1 conditional edge.
3 conceitos: StateGraph · Conditional routing · Human-in-the-loop · Ferramentas: langgraph · MemorySaver · draw_mermaid()
14📅 23/11
Spec-Driven Development e encerramento
Teoria Sem entrega Sem notebook
Aula conceitual e demonstrativa — sem entrega avaliada. O que é Spec-Driven Development (SDD): a especificação estruturada, não o prompt solto, como fonte de verdade para agentes de código. SDD vs. vibe coding vs. prompt engineering direto — quando cada abordagem se aplica. O fluxo spec → plano → tasks → implementação pelo agente → revisão humana. Ferramentas: GitHub Spec Kit, Claude Code, Kiro. Conexão direta com o que a turma já pratica: spec é context engineering aplicado a código — os próprios arquivos SOUL.md/CLAUDE.md usados para gerar o material do curso são um exemplo real.

Demo ao vivo: escrever uma spec curta (requisitos + critérios de aceite) e usar um agente de código gratuito para implementá-la, revisando o diff gerado contra a spec.

Fecha com retrospectiva do semestre completo: do primeiro prompt conceitual ao agente com LangGraph, e os CKPs como portfólio para o mercado.
3 conceitos: Spec como fonte de verdade · Fluxo spec→plan→tasks→implementação→revisão · Ferramentas (Spec Kit, Claude Code, Kiro) · Conexão: evolução direta do Context Engineering aplicado a codificação agêntica
