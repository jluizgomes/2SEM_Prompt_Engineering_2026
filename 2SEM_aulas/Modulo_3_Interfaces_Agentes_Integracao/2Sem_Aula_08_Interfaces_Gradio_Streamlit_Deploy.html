Glossário

gr.Blocks
API de baixo nível do Gradio para layouts customizados — controla a posição de cada componente, ao contrário de gr.Interface e gr.ChatInterface, que já vêm com layout pronto.
yield (streaming)
Palavra-chave Python que transforma uma função em generator — permite devolver a resposta token a token conforme o modelo gera, em vez de esperar o texto completo.
ngrok
Serviço que cria um túnel entre a máquina local (ou Colab) e a internet — expõe uma porta interna como URL pública acessível de qualquer dispositivo.
Analogia: um corredor temporário que liga o notebook fechado do Colab à rua aberta da internet.
share=True
Parâmetro nativo do .launch() do Gradio que gera uma URL pública temporária via infraestrutura da própria Gradio/HuggingFace — alternativa mais simples ao ngrok explícito.
session_id
Chave usada para isolar o histórico de conversa entre usuários simultâneos da mesma aplicação — cada session_id tem seu próprio registro, sem misturar contexto de pessoas diferentes.
RunnableWithMessageHistory
Wrapper do LangChain que adiciona memória de conversa a uma chain originalmente stateless — injeta o histórico correto a cada chamada, buscando pelo session_id.
st.session_state
Dicionário do Streamlit que persiste dados entre os re-renders do script — sem ele, cada interação do usuário reiniciaria as variáveis do zero.
ChatMessageHistory
Classe do LangChain que armazena a lista de mensagens (humano e IA) de uma sessão específica — é o objeto que o RunnableWithMessageHistory lê e atualiza por session_id.

gr.ChatInterface — chatbot com histórico automático

gr.ChatInterface gerencia o histórico de conversa automaticamente e suporta streaming com yield:

gradio_chatinterface.py
import gradio as gr

# A função de chat recebe mensagem + histórico
def chat_rag(mensagem: str, historico: list) -> str:
    """Recebe a pergunta atual e o histórico [{role, content}]."""
    # Por enquanto RAG stateless — Slide 13 adiciona memória com RunnableWithMessageHistory
    resposta = chain_rag.invoke(mensagem)
    return resposta

# ChatInterface detecta automaticamente: função recebe (mensagem, historico) → str
chatbot = gr.ChatInterface(
    fn=chat_rag,
    title="DocMind — Assistente do Domínio",
    description="Pergunte qualquer coisa sobre os documentos do grupo.",
    examples=[
        "Qual é o prazo de entrega mencionado no manual?",
        "Como acionar o suporte técnico?",
        "Quais são as cláusulas de garantia?",
    ],
    chatbot=gr.Chatbot(height=400),
    type="messages",  # formato OpenAI: [{role, content}]
)
chatbot.launch()
💡 type="messages" — padrão moderno
O parâmetro type="messages" usa o formato OpenAI com lista de dicionários [{"role": "user", "content": "..."}] — o mesmo formato do RunnableWithMessageHistory. Facilita a integração com a memória do LangChain.

Streaming com yield — respostas token a token

Sem streaming, o usuário espera a resposta completa aparecer de uma vez. Com yield, cada token aparece conforme é gerado — experiência muito mais responsiva:

❌ Sem streaming
sem_streaming.py
def chat(msg, hist):
    # Espera TUDO antes de retornar
    resp = chain_rag.invoke(msg)
    return resp  # 5-30 segundos

# Usuário: ⏳ (espera 15s) → resposta aparece
✅ Com streaming (yield)
com_streaming.py
def chat_stream(msg, hist):
    parcial = ""
    # .stream() em vez de .invoke()
    for chunk in chain_rag.stream(msg):
        parcial += chunk
        yield parcial  # envia a cada token

# Usuário: "Conf" → "Confor" → "Conforme..."
chatinterface_streaming.py
def chat_rag_stream(mensagem: str, historico: list):
    """Gerador: yield parcial acumulado a cada chunk."""
    parcial = ""
    for chunk in chain_rag.stream(mensagem):
        parcial += chunk  # acumula — usuário vê o texto crescer
        yield parcial

# ChatInterface detecta yield automaticamente e ativa streaming
chatbot = gr.ChatInterface(fn=chat_rag_stream, type="messages",
                             title="DocMind RAG — Streaming")
chatbot.launch()

RunnableWithMessageHistory — RAG com memória multi-sessão

A chain RAG da Aula 06 é stateless. Para que o chatbot lembre da conversa anterior (sem precisar repetir contexto), usamos RunnableWithMessageHistory:

rag_com_memoria.py
from langchain_core.runnables.history import RunnableWithMessageHistory
from langchain_community.chat_message_histories import ChatMessageHistory

# Store em memória — uma entrada por session_id
store: dict = {}

def obter_historico(session_id: str) -> ChatMessageHistory:
    """Retorna (ou cria) o histórico do usuário pelo session_id."""
    if session_id not in store:
        store[session_id] = ChatMessageHistory()
    return store[session_id]

# Prompt RAG com histórico (adiciona {chat_history} ao prompt)
PROMPT_RAG_HIST = """<persona>Assistente do domínio com memória de conversa.</persona>
<historico>{chat_history}</historico>
<contexto>{contexto}</contexto>
<instrucoes>Use o contexto para responder. Cite fontes. Se a pergunta se refere ao histórico, use-o.</instrucoes>
<pergunta>{pergunta}</pergunta>"""

chain_com_hist = (
    {
        "contexto":     retriever | RunnableLambda(formatar_contexto),
        "pergunta":     RunnablePassthrough(),
        "chat_history": RunnableLambda(lambda _: ""),  # preenchido pelo wrapper
    }
    | ChatPromptTemplate.from_template(PROMPT_RAG_HIST)
    | llm | StrOutputParser()
)

chain_rag_memoria = RunnableWithMessageHistory(
    chain_com_hist,
    obter_historico,
    input_messages_key="pergunta",
    history_messages_key="chat_history",
)

import uuid, gradio as gr

def chat_com_memoria(mensagem: str, historico: list, session_id: str):
    """Streaming com memória por session_id."""
    parcial = ""
    for chunk in chain_rag_memoria.stream(
        {"pergunta": mensagem},
        config={"configurable": {"session_id": session_id}},  # chave do histórico
    ):
        parcial += chunk
        yield parcial

with gr.Blocks(title="DocMind RAG") as demo:

    session_id = gr.State(lambda: str(uuid.uuid4()))

    gr.Markdown("## 📄 DocMind — Assistente do Domínio")
    chatbot_ui = gr.ChatInterface(
        fn=chat_com_memoria,

🔮 gr.State — estado por sessão de browser
gr.State(lambda: str(uuid.uuid4())) gera um UUID único para cada nova aba ou sessão de browser que abre a aplicação. O RunnableWithMessageHistory usa esse UUID como chave para manter históricos separados por usuário — múltiplos usuários simultâneos sem interferência.

Streamlit — alternativa com st.session_state

Streamlit tem uma sintaxe mais próxima de scripts Python tradicionais. st.session_state persiste dados entre re-renders:

streamlit_rag.py
!pip install streamlit -q  # rodar como app separado: !streamlit run app.py &

import streamlit as st

st.title("DocMind — Assistente do Domínio")

# Inicializar histórico no session_state (persiste entre re-renders)
if "mensagens" not in st.session_state:
    st.session_state.mensagens = []

# Exibir mensagens anteriores
for msg in st.session_state.mensagens:
    with st.chat_message(msg["role"]):
        st.write(msg["content"])

# Input do usuário
if pergunta := st.chat_input("Faça sua pergunta..."):
    st.session_state.mensagens.append({"role":"user", "content":pergunta})
    with st.chat_message("user"):
        st.write(pergunta)
    with st.chat_message("assistant"):
        resposta = st.write_stream(chain_rag.stream(pergunta))  # streaming nativo
    st.session_state.mensagens.append({"role":"assistant", "content":resposta})

Gradio vs. Streamlit — quando usar cada um

CritérioGradioStreamlit
Instalação e setupRoda inline no Colab com demo.launch()Precisa rodar como processo separado (streamlit run app.py)
ChatInterfaceNativo — gr.ChatInterface em 5 linhasManual com st.chat_message + session_state
File uploadgr.File() — retorna caminho do arquivost.file_uploader() — retorna bytes
Deployshare=True → URL instantâneaStreamlit Cloud ou ngrok manual
Layouts complexosgr.Blocks para layouts customizadosColunas, tabs e sidebar nativos
Para o semestre✅ CKP02, CKP03 — padrão da disciplinaAlternativa válida no diferencial
🎯 Recomendação para o CKP02 e CKP03
Use Gradio — menos fricção no Colab, deploy com share=True em 1 linha, gr.ChatInterface com streaming pronto. O Streamlit é ótimo para dashboards com múltiplos painéis — se o grupo quiser um layout mais elaborado, vai para gr.Blocks antes de migrar para Streamlit.
📖 Fundamentação — Por que o Streamlit não escala como o Gradio
Polzer (RAG with Python Cookbook, O'Reilly, 2026) explica o mecanismo por trás da linha "Deploy" desta tabela: o Streamlit reexecuta o script inteiro do zero a cada interação do usuário — isso simplifica o gerenciamento de estado, mas cria sobrecarga de CPU por usuário, e o autor situa o ponto de saturação em torno de 50 usuários simultâneos. Por isso a recomendação do livro é usar Streamlit para ferramentas internas e provas de conceito, migrando para FastAPI com React quando o público crescer para milhares de usuários ou exigir autenticação refinada. Para os projetos desta disciplina — poucos usuários simultâneos, demonstração em sala — essa diferença de escala é irrelevante; o critério que importa é fricção de setup, e é aí que o Gradio ganha.

📖 Fundamentação — o padrão "Blue and Gold" para deploy seguro
Avila (Architecting AI Software Systems, Packt, 2025) descreve o padrão "Blue and Gold" usado em MLOps para atualizar pipelines de IA em produção sem interromper quem já está usando: a versão Blue continua servindo os usuários normalmente enquanto uma versão Gold é testada em paralelo com os mesmos dados; só depois que as métricas da Gold são validadas contra a Blue é que ela assume o lugar de produção — e a versão anterior fica disponível como rollback imediato caso algo dê errado. Na prática do CKP02/CKP03: nunca sobrescreva a URL share=True que o grupo já divulgou para testar uma mudança arriscada no notebook — rode a versão nova em uma segunda sessão do Colab, valide que as respostas continuam corretas, e só então troque o link compartilhado com a turma.

Perguntas frequentes

PerguntaResposta
"A URL ngrok expira? Quanto tempo dura?"No plano gratuito, a URL expira quando a sessão do Colab termina (timeout de ~90 min de inatividade ou 12h máximas). Para demos ao vivo em sala, é suficiente. Para demonstrações mais longas, usar ngrok pago ou hospedar no HuggingFace Spaces (gratuito, URL permanente).
"Posso usar gr.Blocks para adicionar upload de PDF na interface?"Sim — gr.File(file_types=[".pdf"]) retorna o caminho temporário do arquivo enviado. Na função de upload: carregar com PyMuPDF, dividir, embedar e adicionar ao ChromaDB com db.add_documents(). O desafio do lab pede exatamente isso.
"HuggingFace Spaces é uma alternativa ao ngrok?"Sim, e melhor para URLs permanentes. O Spaces suporta Gradio nativamente — você faz push de um repositório com app.py e requirements.txt e a URL fica no ar permanentemente. O desafio: as API keys precisam ser configuradas nas variáveis de ambiente do Space (não via Colab Secrets).
"O histórico cresce infinitamente? Precisa limitar?"Sim — sem limite, o histórico sofre context rot. Na produção, use ConversationTokenBufferMemory (aprendida na Aula 02) para limitar por tokens. Para o lab desta aula, o histórico ilimitado é aceitável em demo.

# 1. yield — transforma função em gerador (streaming)
def gerar_numeros():
    for i in range(5):
        yield i        # pausa aqui, retorna i, retoma na próxima iteração
list(gerar_numeros())  # → [0, 1, 2, 3, 4]

# 2. Walrus operator := — atribuição dentro de if
if pergunta := st.chat_input("..."):  # atribui E testa ao mesmo tempo
    print(pergunta)  # só entra se pergunta não for None/vazio

# 3. lambda sem argumento — gr.State usa para valor inicial por sessão
uuid_factory = lambda: str(uuid.uuid4())  # chamada a cada nova sessão
estado       = gr.State(uuid_factory)       # sem () — passa a função, não o resultado

# 4. += em string (acumular streaming)
parcial = ""
for chunk in ["Conf", "orme", " a p", "ágina"]:
    parcial += chunk   # acumula: "Conf" → "Conforme" → "Conforme a p" → ...
    yield parcial      # envia o estado acumulado a cada passo

# 5. Dict aninhado como config do LangChain
config = {"configurable": {"session_id": meu_session_id}}
chain.stream(input, config=config)  # config é kw-only, sempre nomeado

O que vem na Aula 09 — Agentes ReAct e tools

🤖 A diferença entre chain e agente
Chain (o que você tem hoje):
Pergunta → retriever → prompt → LLM → resposta
Fluxo fixo, pré-determinado.

Agente (o que vem na Aula 09):
Pergunta → LLM decide qual tool usar → executa → observa → LLM decide próximo passo → ... → resposta
Fluxo dinâmico, guiado pelo raciocínio do modelo.
🛠️ O que você vai implementar
Agente ReAct com 3 tools:
· RAG tool — busca nos documentos do grupo (CKP02)
· DuckDuckGo tool — pesquisa na web quando o doc não tem a resposta

import gradio as gr, uuid

# ── Memória por sessão ──────────────────────────────────────────────
store = {}
def obter_hist(sid):
    if sid not in store: store[sid] = ChatMessageHistory()
    return store[sid]

# ── Chat com streaming + memória ────────────────────────────────────
def chat(msg, hist, sid):
    parcial = ""
    for chunk in chain_rag_memoria.stream(
        {"pergunta": msg},
        config={"configurable": {"session_id": sid}},
    ):
        parcial += chunk
        yield parcial

# ── Interface ────────────────────────────────────────────────────────
with gr.Blocks(title="DocMind RAG") as demo:
    sid  = gr.State(lambda: str(uuid.uuid4()))
    gr.Markdown("# 📄 DocMind — Assistente do Domínio\nPergunte sobre os documentos do grupo.")
    gr.ChatInterface(fn=chat, type="messages", additional_inputs=[sid])

demo.launch(share=True)
