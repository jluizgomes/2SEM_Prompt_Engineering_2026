🧩 O que é um agente ReAct?

ReAct = Reasoning + Acting. O agente:
1. Pensa (Thought) — analisa a pergunta
2. Age (Action) — escolhe uma tool e executa
3. Observa (Observation) — vê o resultado
4. Repete até ter a resposta final

É como um humano que pensa antes de agir, e ajusta o plano conforme novas informações.

💡 Dica do Professor

Uma tool é apenas uma função Python com o decorator @tool. O decorator não muda a lógica — só adiciona metadados (nome, descrição, tipos) que o LLM usa para decidir quando chamá-la.

EXERCÍCIO 01

Tools do domínio ⭐⭐

⭐⭐ — Copie, execute e entenda cada linha.

🎯 Objetivo Pedagógico

Criar ferramentas Python que dão ao agente capacidade de AGIR — não só responder texto. Cada tool é uma "mão" que o agente pode usar.

🧩 Conceitos Trabalhados

🐍 @tool decorator🐍 Docstring como interface🐍 bind_tools()🤖 Tool schema🤖 Function calling

⚙️ Preparação Prévia

Nenhuma dependência nova. Execute o Primeiros Passos acima antes deste exercício.

📋 Passo a Passo no Colab

1Cole o código abaixo e execute — ele cria 2 tools (calcular + busca_web) e vincula ao LLM.
2Teste cada tool isoladamente — antes de conectar ao agente, confirme que cada uma funciona.
3Observe o schema — veja o que o LLM enxerga quando decide qual tool usar.

💻 Código Completo no Colab

2Sem_09_exercicio_01.py · Google Colab
from langchain_core.tools import tool
from langchain_community.tools import DuckDuckGoSearchRun

# ── Tool 1: Calculadora ──
# Esta tool calcula expressões matemáticas simples.
# O decorator @tool adiciona metadados que o LLM usa para decidir quando chamá-la.
@tool
def calcular(expressao: str) -> str:
    """Calcula uma expressão matemática. Ex.: '13 * 17', '2 ** 10'."""
    try:
        resultado = eval(expressao)
        return f"Resultado: {resultado}"
    except Exception as e:
        return f"Erro ao calcular: {e}"

# ── Tool 2: Busca na Web ──
# DuckDuckGoSearchRun é uma tool pronta do LangChain.
# Ela busca no DuckDuckGo e retorna texto com os resultados.
busca_web = DuckDuckGoSearchRun(
    name="busca_na_web",
    description="Busca na web por informações atuais."
)

# ── Juntar todas as tools numa lista ──
# O agente só pode usar tools que estão nesta lista.
tools = [calcular, busca_web]

# ── Vincular tools ao LLM ──
# bind_tools() faz o LLM saber quais tools existem.
# Quando o LLM decidir usar uma tool, ele gera um JSON com nome e argumentos.
llm_tools = llm.bind_tools(tools)

# ── Verificar que tudo está OK ──
print("✅ Tools criadas:", [t.name for t in tools])
print("")

# ── Testar cada tool SOZINHA ──
# IMPORTANTE: teste antes de conectar ao agente!
print("Teste calcular:", calcular.invoke({"expressao": "13 * 17"}))
print("Teste busca_web:", busca_web.invoke("FIAP universidade")[:100])

✅ Output Esperado

✅ Tools criar: ['calcular', 'busca_na_web']
Teste calcular: Resultado: 221
Teste busca_web: [primeiros 100 chars da busca...]

Erro 2: "ModuleNotFoundError: No module named 'langchain_community'"

Causa: Descrição vaga não ajuda o LLM a decidir.

EXERCÍCIO 02

Loop ReAct ⭐⭐

⭐⭐ — Copie, execute e entenda cada linha.

🎯 Objetivo Pedagógico

Implementar manualmente o ciclo Reason → Act → Observe — entender o mecanismo antes de abstrair com frameworks prontos.

🧩 Conceitos Trabalhados

🐍 While/for com condição de parada🐍 ToolMessage🐍 tool_calls🤖 ReAct pattern🤖 Loop de decisão do agente

⚙️ Preparação Prévia

Nenhuma dependência nova — reaproveita as tools do Ex.1.

📋 Passo a Passo no Colab

1Desenhar o loop no quadro — Pensar → Agir → Observar → volta pro início (ou sai para 'Responder').
2Cole e execute o código abaixo — a função agente_dominio() implementa o loop ReAct manual.
3Observe cada passo — o print mostra o raciocínio do agente, não só o resultado final.

💻 Código Completo no Colab

2Sem_09_exercicio_02.py · Google Colab
from langchain_core.messages import HumanMessage, SystemMessage, ToolMessage

# ── Função que implementa o loop ReAct manual ──
# Esta é a ALMA de um agente: o loop while que decide se chama tool ou responde.
def agente_dominio(pergunta: str, max_steps: int = 5) -> str:
    """
    Executa o loop ReAct manualmente:
    1. Envia pergunta para o LLM
    2. Se LLM pede tool → executa tool → volta ao passo 1
    3. Se LLM não pede tool → retorna resposta final
    """
    msgs = [
        SystemMessage(content="Use as tools disponíveis para responder."),
        HumanMessage(content=pergunta)
    ]

    for step in range(max_steps):
        # Passo 1: LLM analisa e decide (Thought + Action ou Final Answer)
        resp = llm_tools.invoke(msgs)

        # Passo 2: Se NÃO tem tool_calls → é a resposta final
        if not resp.tool_calls:
            print(f"  ✅ Resposta final no passo {step+1}")
            return resp.content

        # Passo 3: Tem tool_calls → executar cada tool
        msgs.append(resp)
        for tc in resp.tool_calls:
            resultado = tools_map[tc['name']].invoke(tc['args'])
            print(f"  🔧 Passo {step+1}: {tc['name']} → {str(resultado)[:80]}")
            # Passo 4: Adicionar resultado da tool para o LLM ver
            msgs.append(ToolMessage(
                content=str(resultado),
                tool_call_id=tc['id']
            ))

    return "⚠️ Máximo de passos atingido."

# ── Mapa de tools para acesso rápido ──
tools_map = {t.name: t for t in tools}

# ── Testar o agente ──
print("=" * 60)
print("Pergunta: Quanto é 27 vezes 43?")
print("=" * 60)
resposta = agente_dominio("Quanto é 27 vezes 43?")
print(f"Resposta: {resposta}")

✅ Output Esperado

============================================================
Pergunta: Quanto é 27 vezes 43?
============================================================
🔧 Passo 1: calcular → Resultado: 1161
✅ Resposta final no passo 2
Resposta: A resposta é 1161.

⚠️ Erros Comuns

Erro 1: "AttributeError: 'AIMessage' object has no attribute 'tool_calls'"
Causa: Não chamou llm.bind_tools(tools) antes de usar agente_dominio().
Solução: Execute o bloco de setup do Ex.1 que cria llm_tools.

Erro 2: Agente entra em loop infinito (nunca para de chamar tools)
Causa: O LLM não consegue decidir quando parar.
Solução: O parâmetro max_steps=5 é o limite de segurança. Se acontecer, aumente a descrição da tool ou simplifique a pergunta.

Erro 3: "KeyError" ao acessar tools_map[tc['name']]
Causa: O LLM gerou o nome de uma tool que não existe na lista.
Solução: Verifique se o nome retornado pelo LLM está em tools_map.keys().

💬 Sugestão de Discussão

Esse loop manual é exatamente o que create_react_agent (API do LangChain) faz por baixo dos panos — a diferença é que o framework abstrai o while e o gerenciamento de mensagens.

EXERCÍCIO 03

Agente com LangGraph e MemorySaver ⭐⭐⭐

⭐⭐⭐ — Copie, execute e entenda cada linha.

🎯 Objetivo Pedagógico

Primeira versão do agente como grafo (não loop manual) — antecipa o que será formalizado na Aula 13, já com memória persistente entre sessões.

🧩 Conceitos Trabalhados

🐍 StateGraph, TypedDict🐍 add_conditional_edges🐍 MemorySaver + thread_id🤖 Agente como grafo de estado🤖 Memória persistente por sessão

⚙️ Preparação Prévia

!pip install langgraph — já deve estar instalado no setup.

📋 Passo a Passo no Colab

1Reconectar com o loop do Ex.2 — "O que vocês fizeram com while/for agora vira nós e arestas de um grafo."
2Cole e execute o código abaixo — ele cria o grafo, compila com memória e testa entre 2 chamadas.
3Prove que a memória funciona — a segunda pergunta deve se referir à primeira (o agente lembra).

💻 Código Completo no Colab

2Sem_09_exercicio_03.py · Google Colab
from typing import Annotated, Sequence
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver

# ── 1. Definir o Estado do agente ──
# TypedDict = dicionário tipado. O campo 'mensagens' acumula todas as mensagens.
# Annotated[Sequence, operator.add] significa: ao adicionar, JUNTA as listas (não substitui).
class EstadoAgente(TypedDict):
    mensagens: Annotated[Sequence[BaseMessage], operator.add]

# ── 2. Nó do agente: chama o LLM ──
def no_agente(estado: EstadoAgente) -> dict:
    """Chama o LLM com as mensagens atuais e retorna a resposta."""
    resposta = llm_tools.invoke(estado['mensagens'])
    return {'mensagens': [resposta]}

# ── 3. Nó das tools: executa as tools chamadas ──
def no_tools(estado: EstadoAgente) -> dict:
    """Executa cada tool chamada pelo LLM e retorna os resultados."""
    ultima = estado['mensagens'][-1]
    resultados = []
    for tc in ultima.tool_calls:
        resultado = tools_map[tc['name']].invoke(tc['args'])
        print(f"  🔧 {tc['name']} → {str(resultado)[:80]}")
        resultados.append(ToolMessage(
            content=str(resultado),
            tool_call_id=tc['id']
        ))
    return {'mensagens': resultados}

# ── 4. Função de decisão: tools ou fim? ──
def decidir(estado: EstadoAgente) -> str:
    """Se tem tool_calls → vai para 'tools'. Senão → fim."""
    ultima = estado['mensagens'][-1]
    if hasattr(ultima, 'tool_calls') and ultima.tool_calls:
        return "tools"
    return END

# ── 5. Montar o grafo ──
g = StateGraph(EstadoAgente)
g.add_node('agente', no_agente)
g.add_node('tools', no_tools)
g.set_entry_point('agente')
g.add_conditional_edges('agente', decidir)
g.add_edge('tools', 'agente')

# ── 6. Compilar com memória ──
# MemorySaver armazena o histórico em RAM.
# thread_id = "identificador da sessão". Mesmo thread_id = mesma memória.
memory = MemorySaver()
agente_mem = g.compile(checkpointer=memory)

# ── 7. Função conversar com memória ──
def conversar(session_id: str, msg: str) -> str:
    config = {'configurable': {'thread_id': session_id}}
    r = agente_mem.invoke(
        {'mensagens': [HumanMessage(content=msg)]},
        config=config
    )
    return r['mensagens'][-1].content

# ── 8. Testar memória ──
print("=" * 60)
print("Primeira chamada:")
print(conversar('sessao1', "Quanto é 15 + 27?"))

print("\n" + "=" * 60)
print("Segunda chamada (mesmo session_id = mesma memória):")
print(conversar('sessao1', "E agora some mais 10 no resultado anterior."))

✅ Output Esperado

============================================================
Primeira chamada:
🔧 calcular → Resultado: 42
O resultado de 15 + 27 é 42.

============================================================
Segunda chamada (mesmo session_id = mesma memória):
🔧 calcular → Resultado: 52
O resultado de 42 + 10 é 52.

⚠️ Erros Comuns

Erro 1: "ImportError: cannot import name 'TypedDict' from 'typing'"
Causa: Python < 3.8 não tem TypedDict no módulo typing.
Solução: Use from typing_extensions import TypedDict (já instalado com langgraph).

Erro 2: A segunda chamada NÃO lembra da primeira
Causa: Usou session_ids diferentes (ex: 's1' e 's2').
Solução: Use o mesmo session_id para manter a memória. Session_id diferente = sessão diferente.

Erro 3: "NameError: name 'operator' is not defined"
Causa: Não importou operator.
Solução: Adicione import operator no topo do bloco.
