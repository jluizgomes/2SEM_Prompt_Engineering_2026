EXERCÍCIO 01

HITL com interrupt_before ⭐⭐

⭐⭐

🎯 Objetivo Pedagógico

Implementar a pausa mais simples para aprovação humana: o grafo para automaticamente antes de um nó específico, esperando aprovação.

🧩 Conceitos Trabalhados

🐍 interrupt_before= no compile()🐍 update_state()🐍 invoke(None, config) para retomar🤖 Human-in-the-Loop (HITL)🤖 Checkpointing como base do HITL

⚙️ Preparação Prévia

Reaproveita MemorySaver — já visto na Aula 09, Ex.3.

📋 Passo a Passo no Colab

1Dar um exemplo memorável e concreto — 'Imaginem um agente que pode enviar 500 e-mails de marketing — vocês querem que ele pare antes de mandar, esperando um humano dizer OK.'
2Alunos completam a compilação com interrupt_before — O grafo PAUSA sozinho — não precisa de lógica extra dentro do nó.
3Simular a aprovação com update_state() — Mostrar os 2 passos: 1) rodar até pausar, 2) aprovar e retomar com invoke(None, config).

✅ Gabarito

grafo_hitl=g.compile(checkpointer=memory, interrupt_before=['executar'])
...
grafo_hitl.update_state(config, {'aprovado': True})
r2=grafo_hitl.invoke(None, config=config)

class EstadoHITL(TypedDict):
    solicitacao: str; plano: str; aprovado: bool; resultado: str

def no_planejar(estado):
    r=chat(f'Crie um plano para: {estado["solicitacao"]}',max_tokens=200)
    return {'plano':r,'aprovado':False}

def no_executar(estado):
    if not estado.get('aprovado',False): return {'resultado':'BLOQUEADO'}

    return {'resultado':r}

⚠️ Erros Comuns

Esquecer que invoke(None, config=config) — passar None, não um novo estado — é o que sinaliza 'retomar de onde parou', não iniciar de novo.

💬 Sugestão de Discussão

HITL não é sobre desconfiar do agente — é sobre reconhecer que algumas ações têm consequência real demais para automação total.

EXERCÍCIO 02

HITL com ciclo de revisão ⭐⭐

⭐⭐

🎯 Objetivo Pedagógico

Combinar HITL com loop de revisão (Aula 12, Ex.3) — o humano pode reprovar e pedir ajuste, não só aprovar/negar.

🧩 Conceitos Trabalhados

🐍 interrupt_before + aresta condicional combinados🐍 Contador de versão🤖 Ciclo de revisão humana🤖 Aprovação com feedback

⚙️ Preparação Prévia

Nenhuma dependência nova.

📋 Passo a Passo no Colab

1Diferenciar de Ex.1 — Ex.1 é aprovar/negar simples. Ex.2 permite pedir uma nova versão com base em feedback.
2Alunos completam decidir_revisao() — 3 saídas possíveis: aprovado → finalizar; reprovado com poucas tentativas → gerar de novo; excesso de tentativas → forçar finalização.
3Simular 1 rejeição + 1 aprovação — Ver o conteúdo mudar entre a v1 rejeitada e a v2 aprovada.

✅ Gabarito

def decidir_revisao(e):
  if e.get('aprovado',False) or e.get('versao',0)>=3: return 'aprovado'
  return 'revisar'

class EstadoRevisao(TypedDict):
    tarefa: str; conteudo: str; aprovado: bool; versao: int

def gerar(e):
    r=chat(f'Gere para: {e["tarefa"]}',max_tokens=200,temperature=0.5)
    return {'conteudo':r,'versao':e.get('versao',0)+1}

def revisar(e):
    if e.get('aprovado',False):
        return {'conteudo':e['conteudo']}
    return {'conteudo':e['conteudo']}

#     return 'revisar'

def finalizar(e): return e

g2=StateGraph(EstadoRevisao)
g2.add_node('gerar',gerar); g2.add_node('revisar',revisar); g2.add_node('finalizar',finalizar)
g2.set_entry_point('gerar'); g2.add_edge('gerar','revisar')
g2.add_conditional_edges('revisar',decidir_revisao,{'revisar':'gerar','aprovado':'finalizar'})
g2.add_edge('finalizar',END)

mem2=MemorySaver()
# 👉 COMPLETE AQUI: compile com checkpointer=mem2 e interrupt_before=['revisar']

cfg={'configurable':{'thread_id':'rev-aluno'}}
r=hitl2.invoke({'tarefa':'Email profissional','conteudo':'','aprovado':False,'versao':0},config=cfg)
print(f'V{r["versao"]}: {r["conteudo"][:150]}')
hitl2.update_state(cfg,{'aprovado':True})
r2=hitl2.invoke(None,config=cfg)
print(f'\nAprovado: {r2["conteudo"][:150]}')

⚠️ Erros Comuns

Não ter um limite de versões — sem isso, uma rejeição repetida gera loop sem fim, mesmo com humano no controle.

💬 Sugestão de Discussão

Esse padrão — gerar, revisar, ajustar, repetir — é como equipes reais usam agentes de código hoje (relaciona diretamente com o que vem na Aula 14: Spec-Driven Development).
