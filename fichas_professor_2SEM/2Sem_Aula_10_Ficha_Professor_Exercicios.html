📝 Exercício 1 — Compressão de Contexto com trim_messages

1 Copiar e executar o código

O trim_messages descarta automaticamente mensagens antigas quando o histórico fica grande demais. Copie o código abaixo, execute, e observe o que acontece.

Código completo — copie, cole e execute

# ——— EXERCÍCIO 1: Compressão de Contexto ——— # trim_messages remove mensagens antigas quando o # histórico ultrapassa um limite de tokens. from langchain_ollama import ChatOllama from langchain_core.messages import HumanMessage, AIMessage from langchain_core.messages.utils import trim_messages # 1) Criar o modelo llm = ChatOllama( model="gpt-oss:120b", base_url="https://ollama.com.brcloud.com.br/v1" ) # 2) Função que conta tokens usando o próprio modelo def token_counter(msgs): return llm.get_num_tokens(msgs) # 3) Criar um histórico longo (simula conversa antiga) historico = [ HumanMessage("Qual é a capital do Brasil?"), AIMessage("A capital do Brasil é Brasília."), HumanMessage("E quantos habitantes tem?"), AIMessage("Brasília tem cerca de 3 milhões de habitantes."), HumanMessage("Quando foi inaugurada?"), AIMessage("Brasília foi inaugurada em 21 de abril de 1960."), HumanMessage("Quem projetou a cidade?"), AIMessage("Lúcio Costa projetou o plano urbanístico e Oscar Niemeyer as edificações."), HumanMessage("Qual é a mensagem mais importante desta conversa?"), ] # 4) Ver o tamanho ANTES do trim tokens_antes = token_counter(historico) print(f"📊 Total de tokens ANTES do trim: {tokens_antes}") print(f"📄 Total de mensagens: {len(historico)}") # 5) Aplicar trim: manter no máximo 50 tokens historico_recortado = trim_messages( historico, max_tokens=50, token_counter=token_counter, strategy="last", # manter as ÚLTIMAS mensagens start_on="human", # começar sempre com mensagem humana ) # 6) Ver o tamanho DEPOIS do trim tokens_depois = token_counter(historico_recortado) print(f"📊 Total de tokens DEPOIS do trim: {tokens_depois}") print(f"📄 Mensagens restantes: {len(historico_recortado)}") # 7) Ver quais mensagens sobraram print("\n🔍 Mensagens que sobraram:") for msg in historico_recortado: tipo = "🧑" if isinstance(msg, HumanMessage) else "🤖" print(f" {tipo} {msg.content[:60]}")
→ Saída esperada: 📊 Total de tokens ANTES do trim: 89 📄 Total de mensagens: 9 📊 Total de tokens DEPOIS do trim: 47 📄 Mensagens restantes: 3 🔍 Mensagens que sobraram: 🧑 Qual é a mensagem mais importante desta conversa? 🤖 Brasília foi inaugurada em 21 de abril de 1960. 🧑 Qual é a mensagem mais importante desta conversa?
💡 O que aconteceu?
O trim removeu as mensagens mais antigas (capital, habitantes, projetista) e manteve só as 3 últimas, que cabem em 50 tokens. Se o agente tiver uma conversa longa com o usuário, ele só "lembra" das partes recentes.
2 Modifique e observe

Desafio rápido: Mude max_tokens=50 para max_tokens=100 e execute de novo. Quantas mensagens sobram agora?

Resposta esperada: Com 100 tokens, sobram ~6 mensagens em vez de 3. O trim é proporcional ao limite que você define.

3 Entenda o padrão

O trim_messages é como um "recortador de histórico":

  • strategy="last" → mantém as mensagens mais recentes (descarta as antigas)
  • strategy="first" → mantém as mensagens mais antigas (descarta as recentes)
  • start_on="human" → garante que a primeira mensagem é do humano (evita respostas sem pergunta)

Em agentes reais, isso evita que o contexto fique gigante e o modelo gaste tokens com conversa antiga irrelevante.

📝 Exercício 2 — Seleção Seletiva de Memória

1 Copiar e executar o código

Este exercício cria um agente com MemorySaver que mantém memória por sessão, mas permite filtrar o que o agente "lembra".

Código completo — copie, cole e execute

# ——— EXERCÍCIO 2: Memória Seletiva ——— # MemorySaver armazena o histórico por thread_id. # Aqui criamos 2 threads para mostrar como o agente # separa conversas de usuários diferentes. from langchain_ollama import ChatOllama from langchain_core.messages import HumanMessage, AIMessage from langgraph.graph import StateGraph, MessagesState, START, END from langgraph.checkpoint.memory import MemorySaver # 1) Criar o modelo llm = ChatOllama(model="gpt-oss:120b", base_url="https://ollama.com.brcloud.com.br/v1") # 2) Criar o agente (nó que chama o LLM) def agente(state: MessagesState): resposta = llm.invoke(state["messages"]) return {"messages": [resposta]} # 3) Montar o grafo grafo = StateGraph(MessagesState) grafo.add_node("agente", agente) grafo.add_edge(START, "agente") grafo.add_edge("agente", END) # 4) Adicionar memória memoria = MemorySaver() app = grafo.compile(checkpointer=memoria) # ——— SIMULAÇÃO: 2 usuários diferentes ——— # Usuário 1: pergunta sobre Python print("═══ USUÁRIO 1 ═══") config1 = {"configurable": {"thread_id": "usuario-1"}} resp1 = app.invoke( {"messages": [HumanMessage("Meu nome é Alice e estudo Python.")]}, config=config1 ) print(f" Alice: {resp1['messages'][-1].content[:100]}") resp2 = app.invoke( {"messages": [HumanMessage("Qual a minha linguagem favorita?")]}, config=config1 ) print(f" Alice: {resp2['messages'][-1].content[:100]}") # Usuário 2: pergunta diferente (sessão separada) print("\n═══ USUÁRIO 2 ═══") config2 = {"configurable": {"thread_id": "usuario-2"}} resp3 = app.invoke( {"messages": [HumanMessage("Meu nome é Bob e estudo Java.")]}, config=config2 ) print(f" Bob: {resp3['messages'][-1].content[:100]}") # Bob pergunta pela Alice — NÃO deve saber! resp4 = app.invoke( {"messages": [HumanMessage("Qual o nome da pessoa que estuda Python?")]}, config=config2 ) print(f" Bob: {resp4['messages'][-1].content[:100]}") # Verificar: Alice ainda está na memória dela? print("\n═══ VERIFICAÇÃO ═══") hist_alice = app.get_state(config1) print(f" Alice tem {len(hist_alice.values['messages'])} msgs na memória") hist_bob = app.get_state(config2) print(f" Bob tem {len(hist_bob.values['messages'])} msgs na memória")
→ Saída esperada: ═══ USUÁRIO 1 ═══ Alice: Oi Alice! Python é uma ótima linguagem... Alice: Sua linguagem favorita é Python! 🐍 ═══ USUÁRIO 2 ═══ Bob: Oi Bob! Java é uma linguagem muito usada... Bob: Não tenho informações sobre quem estuda Python... ═══ VERIFICAÇÃO ═══ Alice tem 4 msgs na memória Bob tem 4 msgs na memória
💡 O que aconteceu?
Cada thread_id é uma "caixinha" separada. O Bob não consegue ver o que a Alice disse, porque estão em threads diferentes. O MemorySaver isola a memória por thread_id.
2 Entenda o padrão

O padrão de memória em agentes LangGraph funciona assim:

ComponenteO que fazExemplo
MemorySaverArmazena histórico na RAMSessões de chat
thread_idIdentifica cada sessãoUm id por usuário
get_state()Mostra o estado atual da threadVerificar memória

📝 Exercício 3 — Ferramentas MCP (Simulado)

1 Copiar e executar o código

O MCP (Model Context Protocol) permite conectar ferramentas externas. Neste exercício, simulamos ferramentas MCP usando funções simples.

Código completo — copie, cole e execute

# ——— EXERCÍCIO 3: Ferramentas MCP (Simulado) ——— # MCP é um protocolo para conectar LLMs a ferramentas externas. # Aqui simulamos o conceito com funções Python simples. from langchain_ollama import ChatOllama from langchain_core.messages import HumanMessage from langchain_core.tools import tool from langgraph.prebuilt import create_react_agent # 1) Criar o modelo llm = ChatOllama(model="gpt-oss:120b", base_url="https://ollama.com.brcloud.com.br/v1") # 2) Criar ferramentas simuladas (como se fossem MCP servers) # Em produção, essas viriam de servidores MCP reais @tool def buscar_clima(cidade: str) -> str: """Busca o clima atual de uma cidade (simulado).""" # Simulação: em produção, chamaria API real dados = { "São Paulo": "28°C, parcialmente nublado", "Rio de Janeiro": "32°C, ensolarado", "Curitiba": "18°C, chuvoso", } return dados.get(cidade, f"Clima não disponível para {cidade}") @tool def contar_palavras(texto: str) -> str: """Conta palavras, caracteres e frases de um texto.""" palavras = len(texto.split()) chars = len(texto) frases = texto.count(".") + texto.count("!") + texto.count("?") return f"Palavras: {palavras}, Caracteres: {chars}, Frases: {frases}" @tool def calcular(expressao: str) -> str: """Calcula uma expressão matemática básica.""" try: resultado = eval(expressao) return f"Resultado: {resultado}" except Exception as e: return f"Erro: {e}" # 3) Listar as ferramentas disponíveis print("🔧 Ferramentas MCP disponíveis:") ferramentas = [buscar_clima, contar_palavras, calcular] for f in ferramentas: print(f" • {f.name}: {f.description}") # 4) Criar o agente com as ferramentas agente = create_react_agent(llm, ferramentas) # 5) Fazer perguntas que usam diferentes ferramentas perguntas = [ "Como está o clima em Curitiba?", "Conta as palavras desta frase: O gato pulou o muro", "Quanto é 15 * 7 + 3?", ] for p in perguntas: print(f"\n🧑 Pergunta: {p}") resultado = agente.invoke({"messages": [HumanMessage(p)]}) print(f"🤖 Resposta: {resultado['messages'][-1].content[:150]}")
→ Saída esperada: 🔧 Ferramentas MCP disponíveis: • buscar_clima: Busca o clima atual de uma cidade (simulado). • contar_palavras: Conta palavras, caracteres e frases de um texto. • calcular: Calcula uma expressão matemática básica. 🧑 Pergunta: Como está o clima em Curitiba? 🤖 Resposta: Em Curitiba o clima está 18°C, chuvoso. 🧑 Pergunta: Conta as palavras desta frase: O gato pulou o muro 🤖 Resposta: Palavras: 6, Caracteres: 31, Frases: 1 🧑 Pergunta: Quanto é 15 * 7 + 3? 🤖 Resposta: Resultado: 108
💡 O que aconteceu?
O agente recebeu a pergunta, analisou qual ferramenta usar, chamou a função correta, e retornou a resposta. Isso é o ciclo agêntico: pergunta → decisão → ação → resultado → resposta.
2 Entenda o padrão

O create_react_agent do LangGraph implementa o padrão ReAct:

  • Reason (raciocínio): O modelo decide qual ferramenta usar
  • Act (ação): Executa a ferramenta escolhida
  • Observe (observação): Analisa o resultado
  • Repete até ter a resposta final

Em produção, as ferramentas seriam servidores MCP reais (banco de dados, APIs, etc.), não funções simuladas.

🚨 Erros Comuns e Soluções

Erro 1: ModuleNotFoundError: No module named 'langchain'

ModuleNotFoundError: No module named 'langchain'

Causa: LangChain não está instalado.

Solução:

pip install langchain langchain-community langchain-ollama langgraph

Erro 2: ConnectError: [Errno 111] Connection refused

ConnectError: [Errno 111] Connection refused

Causa: O servidor Ollama não está rodando.

Solução: Verifique se o Ollama está ativo com ollama list. Se não estiver, inicie com ollama serve.

Erro 3: openai.NotFoundError: 404 model not found

NotFoundError: 404 - {"error":{"code":"404","message":"Requested : gpt-oss:120b not found"}}

Causa: Nome do modelo incorreto ou modelo não baixado.

Solução: Verifique com ollama list quais modelos estão disponíveis. Use exatamente o nome que aparece.

Erro 4: NameError: name 'tool' is not defined

NameError: name 'tool' is not defined

Causa: Esqueceu de importar tool do LangChain.

Solução: Adicione from langchain_core.tools import tool no topo do arquivo.

Erro 5: Agente não usa a ferramenta (responde sem chamar tool)

Causa: A descrição da tool não é clara o suficiente, ou o modelo não "entende" quando usar.

Solução: Melhore o docstring da função. Seja específico: "Use quando o usuário perguntar sobre clima" em vez de "Busca dados".

Erro 6: RecursionError no grafo

RecursionError: maximum recursion depth exceeded

Causa: Ciclo infinito no grafo (ex: nó aponta para si mesmo sem condição de parada).

Solução: Verifique se há add_edge criando ciclos sem add_conditional_edges para sair.
