EXERCÍCIO 01

MMR (Maximum Marginal Relevance) ⭐⭐

⭐⭐ — Dificuldade intermediária. Copie o código, execute e observe a diferença entre busca por similaridade pura e MMR.

🎯 Objetivo Pedagógico

Entender por que top-k por similaridade pode trazer resultados redundantes, e como MMR equilibra relevância com diversidade.

🧩 Conceitos Trabalhados

🐍 Algoritmo guloso (greedy) 🐍 max() com key customizada 🐍 Listas e índices 🤖 MMR 🤖 Diversidade de resultados 🤖 Lambda de balanceamento

⚙️ Preparação Prévia

Nenhuma dependência nova — apenas Python puro com math.

📋 Passo a Passo no Colab

1Copie e execute o bloco da função cosine_sim — essa função calcula a similaridade entre dois vetores. Não mude nada.
2Copie e execute o bloco da função mmr — ela seleciona documentos equilibrando relevância com diversidade. O parâmetro lambda_ controla o equilíbrio: 1.0 = só relevância, 0.0 = só diversidade.
3Copie e execute o bloco de teste — observe o output: sem MMR você verá 2 resultados quase idênticos; com MMR, verá resultados mais diversos.

💻 Código Completo no Colab

Código que os alunos executarão no Google Colab. Copie bloco por bloco e execute.

BLOCO 1 — Função de similaridade · Google Colab
# Calcula similaridade cosseno entre dois vetores
import math

def cosine_sim(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    n1 = math.sqrt(sum(x * x for x in a))
    n2 = math.sqrt(sum(y * y for y in b))
    return dot / (n1 * n2) if n1 * n2 > 0 else 0

# Teste rápido:
print(cosine_sim([1,0,0], [1,0,0]))  # → 1.0 (idênticos)
print(cosine_sim([1,0,0], [0,1,0]))  # → 0.0 (perpendiculares)

BLOCO 2 — Função MMR · Google Colab
# MMR: seleciona documentos equilibrando relevância x diversidade
def mmr(query_emb, docs, doc_embs, k=3, lambda_=0.5):
    seleccionados = []
    restantes = list(range(len(docs)))
    sims_query = [cosine_sim(query_emb, e) for e in doc_embs]

    while len(seleccionados) < k and restantes:
        if not seleccionados:
            # Primeiro: pega o mais similar à query
            idx = max(restantes, key=lambda i: sims_query[i])
        else:
            # Próximos: equilibra relevância x diversidade
            sel_embs = [doc_embs[i] for i in seleccionados]
            idx = max(restantes, key=lambda i:
                lambda_ * sims_query[i]
                - (1 - lambda_) * max(cosine_sim(doc_embs[i], s) for s in sel_embs))
        seleccionados.append(idx)
        restantes.remove(idx)

    return [docs[i] for i in seleccionados]
BLOCO 3 — Teste comparativo · Google Colab
# Documentos de teste: A e B são quase iguais, C é diferente
docs = ['Inteligência artificial é o estudo de sistemas inteligentes.',
        'IA é o estudo de sistemas que demonstram inteligência.',
        'Banco de dados relacional usa tabelas e chaves estrangeiras.']

# "Embeddings" fictícios (vetores numéricos) para simular
doc_embs = [[0.9, 0.1, 0.0], [0.85, 0.15, 0.0], [0.1, 0.0, 0.9]]
q_emb = [0.88, 0.12, 0.0]

# SEM MMR: pega os 2 mais similares (A e B — quase idênticos!)
sims = [cosine_sim(q_emb, e) for e in doc_embs]
top2_sem_mmr = [sorted(range(len(docs)), key=lambda i: sims[i], reverse=True)[:2]]
print("SEM MMR:", [docs[i] for i in top2_sem_mmr[0]])

# COM MMR: equilibra relevância x diversidade
resultado_mmr = mmr(q_emb, docs, doc_embs, k=2, lambda_=0.5)
print("COM MMR: ", resultado_mmr)

⚠️ Erros Comuns

Erro 1: TypeError: unsupported operand type(s) for *: 'NoneType' and 'NoneType'
Causa: Esqueceu de importar math no topo do notebook.
Solução: Execute import math antes de tudo.

Erro 2: Resultado do MMR é igual ao sem MMR.
Causa: Todos os documentos são muito diferentes entre si — o MMR só faz diferença quando há redundância.
Solução: Use documentos onde 2+ são semanticamente similares (ex: 2 sobre IA, 1 sobre banco de dados).

Erro 3: ValueError: max() arg is an empty sequence
Causa: A lista restantes ficou vazia antes de atingir k.
Solução: Verifique se k não é maior que o número de documentos.

💬 Sugestão de Discussão

"Se você tem 10 documentos sobre o mesmo tema, qual o valor ideal de lambda? E se os documentos são de temas totalmente diferentes?" — MMR é diferencial, não obrigatório no CKP02, mas para bases grandes costuma melhorar a qualidade do contexto recuperado.

BLOCO 1 — Função de geração QA · Google Colab
import json

def gerar_qa(doc, n=2):
    """Gera N pares pergunta/resposta a partir de um documento."""
    prompt = f'''Documento:
{doc}

Gere {n} pares pergunta/resposta em JSON.
Formato EXATO: [{{"pergunta": "...", "resposta": "..."}}, ...]
A resposta deve estar EXPLICITAMENTE no documento acima.
Retorne APENAS o JSON, sem texto adicional.'''

    raw = chat(prompt, temperature=0.3)
    # Extrai apenas a parte JSON da resposta
    inicio = raw.find('[')
    fim = raw.rfind(']') + 1
    return json.loads(raw[inicio:fim])

BLOCO 1 — Setup ChromaDB · Google Colab

# Documentos de teste (substitua pelos seus)
docs = ['LangChain permite criar chains com LLMs para RAG.',
        'ChromaDB armazena embeddings para busca semântica.',
        'RAG combina recuperação de docs com geração de texto.']

    documents=docs,

BLOCO 2 — Funções de avaliação · Google Colab
# Função RAG: recupera contexto e gera resposta
def rag(q):
    res = col.query(query_embeddings=[embedding(q)], n_results=2)
    ctx = '\n'.join(res['documents'][0])
    resp = chat(f'Contexto: {ctx}\nPergunta: {q}', temperature=0.1)
    return resp, res['documents'][0]

# Faithfulness: a resposta está nos documentos?
def faithfulness(resp, ctx):
    v = chat(f'''A resposta abaixo é suportada pelo contexto?
Contexto: {" ".join(ctx)}
Resposta: {resp}
Responda APENAS: SIM ou NAO''',
        max_tokens=5, temperature=0.0)
    return 'SIM' in v.upper()

# Relevancy: a resposta responde a pergunta?
def relevancy(q, resp):
    v = chat(f'''A resposta responde à pergunta?
Pergunta: {q}
Resposta: {resp}
Responda APENAS: SIM ou NAO''',
        max_tokens=5, temperature=0.0)
    return 'SIM' in v.upper()
BLOCO 3 — Avaliação completa · Google Colab
# Perguntas de teste (5 perguntas — suficiente para aula)
perguntas = ['O que é LangChain?',
             'Como o ChromaDB funciona?',
             'O que significa RAG?',
             'Qual a capital da França?',  # fora do domínio
             'Para que serve embedding?']

print('='*60)
print('AVALIAÇÃO RAGAS — SIMPLIFICADA')
print('='*60)

faith_scores = []
relev_scores = []

for q in perguntas:
    resp, ctx = rag(q)
    f = faithfulness(resp, ctx)
    r = relevancy(q, resp)
    faith_scores.append(f)
    relev_scores.append(r)
    print(f'\nP: {q}')
    print(f'R: {resp[:80]}...')
    print(f'  Faithfulness: {"✅ SIM" if f else "❌ NAO"}')
    print(f'  Relevancy:    {"✅ SIM" if r else "❌ NAO"}')

print(f'\n{"="*60}')
print(f'MÉDIAS:')
print(f'  Faithfulness: {sum(faith_scores)/len(faith_scores):.2f}')
print(f'  Relevancy:    {sum(relev_scores)/len(relev_scores):.2f}')
print(f'{"="*60}')

⚠️ Erros Comuns

Erro 1: Faithfulness = 0.0 para todas as perguntas.
Causa: O LLM está respondendo coisas que não estão no contexto (alucinação).
Solução: Verifique se os documentos são relevantes para as perguntas. Ajuste o prompt do RAG para ser mais restritivo.

Erro 2: Avaliação demora mais que 10 minutos.
Causa: Muitas perguntas (10+). Cada pergunta gera 3 chamadas ao LLM (RAG + faithfulness + relevancy).
Solução: Use no máximo 5 perguntas. No CKP02, 5 perguntas fixas são suficientes.

Erro 3: chat() retorna string vazia.
Causa: LLM Cloud com timeout ou erro de conexão.
Solução: Execute novamente. Se persistir, troque para qwen3:8b no Ollama local.

Erro 4: Relevancy = 0.0 mas Faithfulness = 1.0.
Causa: A resposta está nos documentos, mas não responde à pergunta (resposta genérica).
Solução: Melhore o prompt do RAG — seja mais específico sobre o que perguntar.

💬 Sugestão de Discussão

"Faithfulness abaixo de 0.5 é alucinação significativa e PRECISA ser corrigido antes de entregar o CKP02." — Reforçar isso antes das apresentações começarem. Perguntar: "O que vocês fariam se o faithfulness fosse 0.3?"
